# 照片排序与稳定顺序

对应融合开发分支的 Windows / 本机服务与独立浏览器源码。图库排序现有拍摄时间、导入时间、文件名称和评分；原有影集手动顺序保留。

## 共同规则

| 情况 | 行为 |
| --- | --- |
| 已知值 | 按所选字段升序或降序 |
| 相同值 | 始终按稳定照片 ID 升序，与导入 / 请求返回顺序无关 |
| 缺失值 | 两个方向都放最后，不把空评分当成零分 |
| 已登记的零分 | 作为有效数值排序，和没有评分区分 |
| 文件名称 | 使用固定 Unicode 码点顺序，与 SQL BINARY 对齐，不随界面语言或系统排序设置变化；数字字符按文本排列 |
| 手动影集 | 按成员保存的位置，暂不受全局升降序影响；查看评分排序不会重写这些位置 |
| 未知排序参数 | 回退到拍摄时间，不把任意元数据字段当作排序键 |

评分沿用现有星标操作；点击当前分数可以清除。评分排序下修改 / 清除分数后刷新 ID 顺序，按评分筛选时也刷新结果；选中状态按照片 ID 保留，信息抽屉继续显示当前照片。跨图库不恢复另一图库的选中状态。

排序字段与方向保存在各图库的浏览偏好中，复用既有库身份与会话检查。A→B→A 或重载后分别恢复，不移动原片、不创建新的数据表。

## 分页与开销

Native `/photos/ids` 使用只选 ID 的 SQL 查询，不创建所有 Photo 对象；页接口保留数据库 offset / limit，完整记录、成员和标签仅水合请求窗口，`by-ids` 按请求次序返回。数据库仍需执行排序和 offset 遍历，这不是游标分页，也不是常数时间查询的保证。

独立浏览器对已打开清单中的对象引用排序，分页之后才生成照片结果；不会为了深页读取原片或缩略图。手动影集位置先建立映射，避免排序比较中反复扫描成员列表。浏览器清单整体读取 / 排序和实际超大库性能继续在相应后续阶段评估。

## 验证

共同 JSON 夹具由真实 SQLite API 与前端逻辑分别检查，覆盖相同时间 / 名称 / 分数、空值、零分、中英文及补充平面的 Unicode 字符。1027 条重复值数据在升降两个方向逐页拼接，结果与 ID 接口一致，无重复或漏项；Native 另检查深页 ORM 加载数和 ID 查询零水合，浏览器检查原片 / 缩略图零读取。

实际界面覆盖中文深色宽屏、英文浅色窄屏、重载、选择保持、修改 / 清除后重排、A→B→A 和相同记录 ID 的图库隔离。手动位置与真实合成原片哈希保留。详细批次结果见 [融合实施记录](afterframe-upgrade.md)。
