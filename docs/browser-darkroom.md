# 光影集网页版：作品展示与数字暗房

本次改造延续现有纯浏览器、本地优先架构。首页参考摄影网站的大幅封面、透明导航、深色与金色层次，保留光影集品牌；没有复制参考站的照片、文案或打包代码。

## 启动与使用

```powershell
npm run build:web
npm run preview:web
```

在桌面 Chrome / Edge 打开 `http://127.0.0.1:4175/`。开发模式为 `npm run dev:web`（5175）。生产文件位于 `frontend/dist-web`，不能通过双击 HTML 使用目录权限、Worker 和 RAW。

目录授权按浏览器、浏览器配置和网站地址保存，不会从 Edge 自动共享到 Codex 内置浏览器。在 Edge 创建的图库建议继续用原来的 Edge 和同一地址打开。权限过期时，启动页提供“重新授权并打开上次图库”；没有授权记录时，选择包含 `library.json` 的数据目录。取消或拒绝目录选择不会触发元数据恢复提示，也不会修改图库文件。

打开图库数据目录后，旧照片仍可能需要原片目录授权。照片详情显示“原片目录尚未授权或连接”时，点击“前往原片授权设置”，在“原片目录（只读）”为每条记录选择原来存放照片的文件夹。图库数据目录与原片目录分别授权；预览能显示不代表已经取得原片访问权限。原片路径未变化时无需重新导入，标签和影集继续保留。水印工坊和水印图库也提供原片授权设置入口。

1. 新建空的数据目录，或打开已有浏览器图库。原片目录单独授权，保持只读。
2. 导入可以选择多张照片或一个文件夹。多选文件会在图库的 `photos` 目录保存原始字节副本，随图库备份；文件夹导入仅关联原片路径。任务先统计支持的照片总数，再开始去重、读取 EXIF 与生成预览；重复和损坏照片计入固定总数，分别显示跳过或失败。不支持的扩展名不计入照片总数。
3. 导入后，在首页“策展首页”选择最多 12 张照片并排序；清空选择恢复最新照片。首页作品来自当前用户的本地图库，不会自动变成公开相册。
4. “工具”包含“光影暗房”、水印工坊和水彩工坊。光影暗房合并照片分析与仿色、RAW 显影和摄影后期，保留直方图、EXIF、参考图、全部编辑参数和导出功能，完全在本机处理。可以打开单个照片 / RAW，也可选择图库照片；当前融合分支的图库批量导入也支持 RAW，预览与 16 位编辑源分开，见 [RAW 入库说明](raw-import.md)。
5. “保存编辑”保存参数。外部单文件会保留只读输入副本到数据目录 `drafts/edits`，便于重开和备份；图库照片继续引用原片。参考图只保存颜色统计，不保存参考图本身。
6. “另存并下载”写入数据目录的 `exports`，重名自动编号。发送水印或水彩会先另存编辑副本到图库，再打开对应工坊；不会自动调用水彩服务。

直接链接使用 hash 路由：`/#/tools`、`/#/tools/darkroom`。旧的 `/#/tools/analyze`、`/#/tools/raw`、`/#/tools/edit` 和对应 `?page=` 链接均进入光影暗房。

水印工坊的署名选项直接显示对应字体，不必先点击选中。第二种“沉浸光感”水印取消署名后保持相同的画布尺寸、照片位置和两侧信息排版，仅移除中间署名。预览、另存和批量导出共用此布局。

## 图像处理与边界

- RAW 使用固定 `libraw-wasm@1.6.0`：16 位、线性 sRGB 解码、相机白平衡、关闭自动提亮。不是使用内嵌 JPEG 冒充 RAW 解码。
- 独立 Worker 持有当前源像素；预览最长边 2048，导出从源像素重新计算。曝光与白平衡在浮点线性值上调整，后续色调、曲线、HSL 和仿色最终输出 8 位 sRGB JPG / PNG。
- 曝光范围 ±5 EV；白平衡是相对色温/色调控制，不是相机标定的绝对 Kelvin。曲线有五个节点。HSL 为全局控制，未包含分色通道或局部蒙版。
- 仿色使用 Lab 均值 / 标准差迁移，支持强度和保留亮度；它不能重建参考图的布光或内容。平坦区域的方差处理避免除零。
- 直方图与裁切比例基于当前预览像素；任一 RGB 通道接近边界即计入裁切，数值不是传感器的原始饱和度测量。
- 锐化与降噪是基础邻域处理，不是 AI 去噪。没有图层、PSD、液化、修复画笔、全景或堆栈合成。
- 输入限制 256 MiB、1 亿像素；实际可用大小也取决于浏览器内存。失败或取消后可以重新打开文件。没有静默缩小用户要求的导出尺寸；最长边 0 表示原尺寸。
- 编辑撤销最多保留 100 个参数状态。历史不保存全尺寸位图。编辑参数持久化，撤销历史只在当前会话中保留。
- 图库清单当前为 version 4，保留可选 `showcase`、`edits` 和派生照片的 `managed_path`；照片 / 草稿来源规则与 recipe 分开。旧 version 1 / 2 / 3 可读，首次写入先保留升级前原始元数据，旧工程和旧照片输入不变。新增条件集合规则与来源解码版本分别保存。清单 revision 冲突拒绝写入，并继续保留上一份元数据；详见 [编辑源解码版本](source-decoding.md)与[条件集合](rule-collections.md)。
- 删除编辑记录、照片记录或更改策展不会删除原片。编辑临时源和派生文件目前保留在数据目录，不自动回收未引用文件。

## 静态托管要求

`edgeone.json` 已包含跨源隔离响应头：

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

WASM 使用 `application/wasm` MIME。页面 CSP 保持限制；仅 `/raw-1.6.0/*` 的 Worker 资源响应允许上游 Emscripten/Embind 所需的动态函数和 WASM 编译。不要把该策略扩大到整个页面。若换托管平台，必须迁移这些响应头，不能只复制 HTML。

RAW 的脚本和 WASM 同源部署并首次使用时缓存；第一次解码完成后可离线重开。更新版本时，Service Worker 根据构建与响应头摘要切换缓存并移除旧缓存。

相关许可证和源码链接在 `frontend/public/licenses/raw`，构建后随 `/licenses/raw/` 分发。LibRaw 的包级支持不保证每一台相机、压缩方式或损坏文件都能解码。

2026-10-16 五项体验修正已验证：多选文件导入、固定照片总数、署名字体即时预览、统一光影暗房、沉浸光感无署名布局。新增用例覆盖去重与损坏文件、取消导入、文件副本重开与备份哈希、旧链接、首次打开字体加载，以及横幅/竖幅/全景水印的像素对比。无署名 PNG 与有署名 PNG 在中心署名区域外逐像素一致，尺寸相同；预览尺寸也一致。

本轮前端逻辑 11 项、后端 74 项、桌面浏览器 33 项及图标 1 项通过。网页版共 26 项：首次全量执行 25 项通过，1 项因备份按钮文案变化需更新定位；修正后，该项和工具布局相关的 2 项复验通过。`build:web`、桌面 `build` 与 `git diff --check` 通过。实际检查了中文深色桌面、英文浅色窄屏、导入对话框和首次打开的署名字体截图。测试和截图仅使用合成照片；RAW 回归使用已记录来源的四种公开样本。

```powershell
npm run test:web:fixtures # 下载公开 RAW 验证样本，校验大小与 SHA-256
npm run test:frontend

npm run test:web

```

公开样本来源与校验值见 `frontend/tests/raw-fixtures.json`。DNG 来自 LibRaw-Wasm 的合成有损 DNG 测试；CR2、NEF 来自 rawpy 测试集；ARW 来自 LibRaw-Wasm 示例。仅保存在忽略的 `.test-artifacts/raw-fixtures`，不随应用发布。没有样本时真实 RAW 用例会明确跳过，其余用例使用合成图片。

验证内容包括：四种 RAW 的真实 16 位解码、WASM 缓存与离线 DNG、预览和导出一致性、原图哈希、损坏文件、取消恢复、参考图仿色、编辑恢复、跨窗口冲突、备份、策展排序、图库与灯箱、双语/双主题和窄屏。水彩沿用模拟流程回归，不表示已验证真实付费模型画质。

本次视觉检查保留在 `.test-artifacts`：参考站桌面/窄屏截图，以及浏览器测试生成的首页、工具、编辑器、图库和灯箱截图。项目截图使用明确的合成风景图，没有使用私人照片。参考站的构图、导航和排版作为风格依据；本项目保留自己的内容与功能布局，不声称逐像素复制。
