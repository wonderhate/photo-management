# 人工描述、标注记录与标签来源

此功能属于 AfterFrame 融合开发分支，适用于 Windows / 本机服务和独立本地网页版。入口位于原有照片信息面板，保留现有查看器、悬停信息栏及配色。

## 人工描述

在「人工描述」填写文字并保存。人工内容优先于 AI 描述；留空后保存也是有效决定，之后重新标注不会重新填上文字。「恢复使用 AI 描述」将人工覆盖设为 NULL，显示当前 AI 描述；尚无标注时显示空白。

人工描述最多 4000 个字符。编辑中的文字不会因后台标签变化丢失；保存失败保留草稿，可由用户重试。输入描述时 P / X / U 等照片快捷键保持输入保护。

批量编辑增加四种描述操作：保持、设置、清空并保持空白、恢复使用 AI。默认保持原描述。批量目标继续固定为打开弹窗时选择的照片。

## 标签与拒绝记录

原有逗号分隔的标签编辑保留。点击「保存标签」表示确认整份列表：保留的标签转为人工来源，删掉的标签进入拒绝记录。现有收藏、评分、颜色和选片标记独立保存。

「标签来源与确认」区分人工和 AI：可以将单个 AI 标签「转为人工」，也可以移除某个标签。批量添加只将明确添加的标签转为人工，其他 AI 标签保留来源；批量移除也会记录拒绝，包括当前尚不存在的同名标签。

重新标注只替换上一轮仍归 AI 管理的标签，保留人工标签，不会自动加回已拒绝的名字。「重新允许」撤销相应拒绝；当前 AI 记录仍建议此标签时立即恢复，否则等待后续标注。手动重新添加标签则直接变为人工来源。拒绝记录上限 5000 个，超过时失败并保留原状态，不静默丢弃决定。

沿用现有标签的大小写语义，不把不同大小写或中英文翻译自动视作同一标签。保留旧网页版人工标签最多 200 字符、完整编辑最多 200 项的能力，本机服务同步支持；新人工输入去首尾空白，按准确名字去重。AI 每轮标签仍限定最多 100 项、每项 100 字符，不截短已存在的人工长标签。当前规则集合、标签筛选和统计继续使用有效标签列表。

## AI 记录与接口

有记录时，「AI 标注记录」显示模型、供应来源、描述及识别文字。描述与识别文字按普通文本展示。当前这一步完成本地记录、来源合并与人工保护；调用国内视觉模型、选范围执行及任务进度属于后续 AF52 / AF53，不会因导入或打开照片自动请求 AI。

`POST /api/photos/{id}/annotation`（本机服务）及对应浏览器本地 API 保存已经取得的结构化结果，本身不读取或上传照片，也不调用模型。请求包含：

- `version: 1`、`expected_revision`、照片当前目录记录的 `source_hash`。
- `caption`（最多 4000 字符）、`tags`（最多 100 项）、可空 `detected_text`（最多 20000 字符）。
- 非空 `provider` / `model` 标识，不接受密钥或额外字段。

保存时检查照片身份和标注 revision，成功后 revision 加一，并在同一写入中合并最新人工标签和拒绝记录。旧结果或其他照片的哈希不能覆盖当前标注；这项检查绑定目录记录，不替代未来模型任务读取像素时的源文件哈希验证。迟到的标注也不能覆盖人工描述，包括人工空描述。浏览器继续使用现有图库会话和清单 revision，切库或其他窗口写入后拒绝旧保存。

整理信息按已有照片文件记录保存，不自动将 AI 结果复制到另一份 RAW / JPEG；不回写原照片或 XMP，不因删除整理记录删除原片。

## 数据升级与合并

AF21 的 SQLite schema **9** 增加 `photos.user_description`、`photos.annotation`、`photos.rejected_ai_tags` 及 `photo_tags.origin`。升级前备份、失败回滚、重复执行保持已有决定。旧标签没有来源历史，按人工保护；不将其推断为 AI 标签。

AF21 的浏览器 manifest **8** 可读旧 1–7 格式。旧缺省来源在 API 输出中按人工保护，读取不修改旧清单。首次写入先保存旧 `library.json` 的完整原始字节到 `library.before-annotations-v8-*.json`；备份失败不发布新清单。未来格式、旧格式冒用新字段、无效标注 revision / 来源以及同时生效又被拒绝的标签均拒绝覆盖。

当前版本随[本地人物模型保护](face-model-spaces.md)及[连续切图保存基础](seamless-split.md)升级至 SQLite **16** / browser manifest **11**，可读旧清单 1–10，原有标注及来源字段继续保留。

库合并保留目标照片的描述覆盖、标注和拒绝记录，包括空字符串或 NULL；来源库不能重新填回目标已拒绝的标签。两库同名标签以人工保护优先。新照片保留来源信息；旧来源库缺少新字段时补空记录和人工标签来源。现有影集、人物、草稿、作品及原片关系继续保留。

## 验证范围

共享 JSON 操作向量核对 Python SQL、TypeScript 与浏览器本地 API 的人工覆盖、标签来源及拒绝行为，包含与 JavaScript 属性同名的标签。合成原片检查 API、批量、重标注、版本冲突、备份失败、升级幂等、库合并及 SHA-256；中英文深浅主题、宽窄屏检查实际界面。模拟标注只证明保存和合并规则，不作为真实模型识别质量、联网或付费调用验收。

完整进度见[融合实施记录](afterframe-upgrade.md)。
