# 连续切图：交互、整组输出与分片独立编辑

开发分支已在暗房中加入“无缝分图”入口，两端共用交互界面、Worker 和整组保存。支持比例、张数、选区、预览条、保存组重开、单片下载、整组目录输出，以及分片独立继续编辑与父子工程往返。原配色、照片浏览器、普通裁剪与启动展示页保持。本批已通过源码运行环境的完整回归。

## 图像处理

分图使用旋转、翻转及自由校正后的来源，独立于普通裁剪框。默认单片比例 3:4，另有 1:1、2:3、9:16、4:5 及自定义宽高；自动或手动 2–10 片。四角等比调整、区域平移、中心保持与旋转边界约束使用同一套坐标。鼠标 / 触控一次拖动对应一次撤销；Esc 先取消正在进行的拖动，空闲时关闭工具。方向键逐像素调整，Shift 加速；比例宽高允许 1–100 的小数，并按图库保留上次选择。分图撤销历史与普通编辑历史独立。

渲染先处理完整覆盖区域，再按累计整数边界逐片切出。这样锐化 / 降噪在接缝两边使用相同邻域。余数分配到各片，每一列恰好属于一片，最多相差一列。TypeScript 与 Python 共用正数半像素向上舍入契约，避免两端四舍五入差异。

后台线程冻结本次参数，保留完整 PNG 母版，再依次编码 PNG 或白底 JPG 分片，并计算每个文件的 SHA-256。PNG 可逐字节拼回母版；JPG 有损压缩，不承诺解码像素逐字节相同。单组编码文件总量最多 512 MiB，单幅像素沿用 1 亿上限；编码画布逐个释放。生成期间取消会终止线程及其等待任务，自动恢复暗房线程并保留工程和普通编辑参数；来源保存及整组提交阶段等待事务结果，不伪装为已经取消。没有模型、网络图片上传或付费请求。

## 整组保存

每组固定原工程 ID / 版本、源内容哈希、解码规则、原参数、实际渲染参数、覆盖区域、整数边界、输出格式 / 质量、母版及有序分片。后续修改原工程不改变已保存的分图。母版是组内资源，不额外算作一张原照片；分图文件也不写入原片路径。

本机服务复用 `AssetVariant`：一个 `split-master` 加上有序 `split` 行。只在新建受管理 UUID 目录里写文件，检查文件哈希、格式、尺寸和 PNG 分片像素，复核工程版本及只读源快照后一次提交全部记录。失败清理本次新文件，保留既有作品。相同请求 ID / 内容再次提交返回同组，内容冲突拒绝覆盖。数据库复制 / 合并保留不可变存储 ID，并重新映射整组逻辑 ID 关系。

独立浏览器将完整组记录保存到清单的 `splits`，图像放在 `drafts/splits/<UUID>/`。先写全部受管理文件，再以现有图库提交锁发布一次清单；失败撤销本次新建的组目录。整个过程绑定开始时的目录、图库身份和会话，关闭 / 切库后的旧操作不会写入新库。读取保存的组会核对全部文件哈希；图库完整备份包含这些文件。关联图库照片首次保存分图时，另存一个私有源快照，后续组复用。移出照片记录会将被分图引用的工程解除照片关联，保留源快照和分图；原片不移动、不删除。源快照不能通过派生图像地址下载，重开工程仍沿用原文件名及解码规则。原工程仍被分图引用时禁止直接删除工程记录。

分图保存与父工程保存按同一工程锁串行化；两者都核对开始时的图库身份和工程版本，迟到写入不能使已经移除的记录重新出现。保存响应不确定时，界面保留编码结果及请求 ID；用户主动重试复用同组，不生成重复作品。

重开已保存的编辑记录，再进入“无缝分图”，可分页查看此照片的分图组。选择组展示保存时的分片，不随上方实时调整改变。单片下载沿用图库内文件；也可直接点击对应分片的“继续编辑分片”。完整目录输出与独立编辑见下文。

浏览器校验上传结果的冻结参数、哈希、格式和解码尺寸；PNG 像素拼接一致性由共享 Worker 与真实编码检查覆盖。本机接收端额外逐像素比较 PNG 母版切片。两者都不声称可从上传的 JPG 字节反证全部图像处理过程。

## 整组目录输出

先保存或选中一组分图，再在“导出整组”中输出。默认沿用当前应用的导出目录；“选择分图目录”只在主动点击后打开选择器。取消选择保留先前目录。默认勾选“为整组创建子目录”，也可以取消勾选，直接输出到所选目录。选择目录本身不会写文件或开始导出。

输出直接复制已保存的 PNG / JPG 字节，不重新渲染、缩小或压缩。子目录默认命名为 `<照片名>_split`，分片按两位数字排序；若子目录或任意分片名称已被占用，整组统一增加编号避让。既有文件和照片原片不覆盖，改变上方选区也不会影响正在输出的保存组。

本机端先排他占用整组新文件名，写入并校验全部内容后登记下载地址和本次回执。相同导出请求重试会核对已有输出，不重复创建一组；文件或回执已变化时拒绝覆盖，可主动“另存一组”。失败清理能够确认属于本次写入的新文件并恢复登记；比较文件身份及源字节前缀，已有文件和外部改动保留。回执位于现有 `export-records` 的子目录中，随库复制保留；自选外部目录内的文件仍需单独备份。

独立网页版按所选目录授权写入，同源窗口之间串行导出，并与图库默认导出锁协调。浏览器没有原子排他建名接口，因此同时使用同名检查、迟到文件检查、排他写入、完整输出校验和文件身份检查；已经被外部修改的文件不会在回退时删除。选择器返回的目录及重试回执只属于当前图库会话，关闭 / 切库后不能复用；未完成请求仍只回退开始时拥有的新文件。默认图库内 `exports` 会随完整备份复制，另选目录不会自动纳入图库备份。

这里的整组回退指应用捕获到写入、校验或登记失败后的处理，不代表多文件复制具有文件系统单次原子提交能力。进程被强行终止时，目标目录可能保留本次未完成的文件；图库内的保存组仍可用于重新导出。图像生成与目录复制分开，已确认保存后释放编码大图缓存。

## 单片继续编辑与版本来源

两端均可从一个已保存分片创建独立工程。点击“继续编辑分片”前，界面会保存当前暗房中尚未保存的调整，再复制保存分片的原始编码字节到新工程私有目录，从中性编辑参数和已归正的解码规则开始；原分片已经包含调色、旋转和裁剪，不再叠加一次父工程效果。上方未保存的分图选区属于临时工具状态，继续编辑以所选保存组为准。单片输入沿用暗房 256 MiB 上限，超限时拒绝创建，不悄悄缩图。已保存的分图和原片不被更改，创建子工程不额外增加图库照片计数。

`derived_from` 单独标记版本，固定父工程 ID / 版本、分图组、分片 ID / 序号、母版哈希、父源哈希、分片哈希及尺寸。以后修改父工程不会改变子工程的来源；子工程再次分图可继续形成来源链。读取、保存及重新生成副本前检查关系和版本，未知版本或断开的关系拒绝使用。子工程自有快照完整时，旧分片文件损坏不影响已有子工程读取；从损坏分片创建新工程则失败。

创建请求带固定 UUID：响应丢失后重试返回同一工程，并保留其中已经保存的新调整；相同 ID 指向不同分片时拒绝覆盖。复制或数据库提交失败撤销本次新工程目录；已存在的目录不会覆盖。库复制保留独立快照，库合并重新映射每一代的逻辑来源 ID，并保留不可变存储 ID。离线维护的关系校验不加载应用配置、默认图库或 Web 服务。

来源栏显示分片序号、分割时的父工程版本和当前子工程版本。“返回父工程（当前版本）”先保存子工程调整，再打开父工程的最新版本；它不会把父工程回滚到旧参数。随后可用“返回分片编辑”回到刚才的子工程。关闭后可从暗房的已保存编辑列表重开子工程；来源关系仍然保留。

网页版新增完整来源关系校验，拒绝未知版本、损坏哈希、错误路径、缺失父记录及循环引用。其私有源文件随完整图库备份复制。发送到水印等已有工坊时，仍按原流程另存一张作品照片，同时冻结子工程的参数、版本和来源；水印草稿及水彩作品保存这份来源说明。已有输出引用子工程时禁止移除编辑记录。浏览器写入清单后若返回异常，先精确核对落盘内容；确认提交成功便保留源快照，不误清理已发布工程，结果仍无法确认时保留文件供恢复。

## 当前存储版本与兼容

融合开发分支当前为 **SQLite schema 21 / browser manifest 17**。本机 schema 15 引入整组分图来源，16 为分片继续编辑增加来源关系的版本保护，17 支持自由文字配方 v3，18 支持文字 / 蒙层配方 v4，复用原表，不重写旧副本；浏览器 11 引入组记录及编辑版本号，12 引入子工程及作品的来源关系，13 保护文字配方与含文字输出，14 保护混合图层。旧浏览器工程没有版本号时按 0 读取，后续显式保存递增。

本机升级沿用备份、事务和幂等迁移；浏览器可读清单 1–14，第一次写入 14 前完整保留原 `library.json` 字节到 `library.before-layer-stack-v14-…json`；从 13 之前格式升级时也保留 `library.before-text-layers-v13-…json`；从 12 之前格式升级时也保留 `library.before-edit-lineage-v12-…json`；从更早格式升级时仍保留相应的 `library.before-splits-v11-…json` 等备份。备份失败不发布新清单。旧格式冒用新字段、未来格式、损坏几何 / 关系或重复 ID 拒绝读取。普通配方 v1 / v2 保持原契约；v3 明确加入自由文字，源解码版本仍分别管理，原有首次构图 v2 备份也继续保留。含文字时，母版先绘制映射后的完整文字再切片；父配方冻结文字、实际照片几何配方保持 v2。分片子工程从已烘焙文字的中性快照开始。详见[自由文字操作与限制](shared-darkroom.md)。

## 检查与剩余工作

合成库检查覆盖真实 PNG / JPG 编码、透明通道拼接、旋转与校正、调用后参数变动、进度与取消、重复 / 并发请求、过期工程、原片和源快照哈希、写入中断、备份失败、复制 / 合并、完整备份重开、切库时回滚以及损坏文件拒绝恢复。

源快照保留已有七项真实浏览器专项检查，包括移出记录、保存、备份重开、源文件变化、并发保存、存储失败、关闭 / 切库和错误路径。界面专项检查覆盖中英文、明暗主题、宽窄布局、手势撤销 / 取消、普通裁剪不变、比例持久化、保存组重开、下载字节及原片哈希。目录输出专项覆盖两种格式、同名 / 迟到冲突、输入变化、写入 / 登记 / 回执失败、写入完成但返回异常、外部改动保留、切库、原片哈希和两端中英宽窄交互。单片继续编辑覆盖中性参数实际像素、未保存调整保护、父子往返、刷新恢复、并发同请求、多代来源和备份重开；AF33 已通过当前源码运行环境验收。自由文字联合批次又验证了父文字坐标映射、旋转裁切后的母版与分片拼接、含文字子工程及完整备份重开。当前完整前端逻辑 128 项、本机界面 175 项、独立 Web 180 项、后端 294 项通过。WebP 和统一导出元数据策略继续归入 AF74，不将当前 PNG / JPG 支持写成全部格式完成。完整批次结果和后续范围见[融合实施记录](afterframe-upgrade.md)，真实 WebView2 / 发行安装包仍单独验收。
