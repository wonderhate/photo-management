# 批量忽略与恢复人物分组

Windows 桌面及连接本机服务的网页支持此功能。独立浏览器图库仍没有人物模型与人物分组，本次不增加云端分析或自动上传。

## 操作

在“人物相册”点“批量忽略分组”，搜索并勾选分组，检查当前名称后点“忽略所选分组”。一次最多 100 个，列表每页 40 个，选择可跨页保留；可以主动取消全部选择。多人同时整理或后台分组已变化时，旧请求会被拒绝，选择保留；刷新后重新检查再提交。

“已忽略分组”列出保留的分组记录，支持文字搜索和分页。勾选并检查后，点“恢复所选分组”。恢复只移除忽略状态和对应的阻止重建记录，重新显示已有成员；不会下载模型、读取图片来重新识别，也不会重建已被删除的照片记录。忽略和恢复均记入现有的“整理记录与撤销”，撤销仍会检查后续冲突。

被忽略的分组从普通人物列表和待确认区隐藏，不参加新照片的自动正向分组。名字、成员、原确认状态、封面及各模型来源参考继续保留。需要改名、确认、合并、移出、关联或删除这个人物时，先恢复，避免无意破坏忽略决定。已有影集、作品与明确的人物照片范围仍可读取；影集成员、顺序、封面和原人物关联不被改写。

## 为什么重扫不会立即恢复错误组

`face_ignores` 保存人物的忽略决定，`face_ignored_members` 保存原片内容哈希、模型来源、人脸位置、向量、原确认状态及稳定观察摘要。后者独立于照片记录和人脸观察的删除关系，因此清理分析缓存、删除观察行，或移除库记录后重新登记同一原片，都不会顺带清除这个决定。

重扫时先按**相同原片内容和相同模型空间**找旧决定，再检查观察摘要。检测顺序变化不影响匹配；少量数值抖动可用高度重合的位置及高度一致的向量核对。同一原片里的其他人脸，以及其他原片或其他模型来源，不会仅因看起来相似而被全局忽略。

旧来源不明的人脸继续保留，沿用原来的跳过已分析保护；不会猜测其向量属于当前模型。换成不同来源模型的新观察需要独立检查。这套机制保护人工决定，不代表真实识别准确率已经提高。

## 数据与迁移

上述两表由 schema 14 引入；当前随[连续切图保存基础](seamless-split.md)更新为 **schema 21 / manifest 17**。升级，先备份；备份失败不写，重复升级保持幂等。旧人物、人脸、模型来源、封面、影集和已保存的 schema 13 撤销记录继续有效。没有忽略状态时，原撤销摘要保持原格式。

批量操作及撤销在本机单个事务中核对版本并写入，任一步失败全部回滚。忽略关系和向量属于私人图库元数据，不写入 Git、发布物或公开作品。

复制图库保留决定及历史。合并图库映射人物和模型来源，目标已有的“正常 / 已忽略”决定优先；导入到已忽略人物的新成员也保存对应阻止重建记录。来源库的撤销记录留在来源备份中，避免跨库重放旧 ID。
