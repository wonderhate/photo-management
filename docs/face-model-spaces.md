# 本地人物识别与模型来源保护（融合开发分支）

Windows 与本机服务继续使用现有 OpenCV YuNet / SFace，在本机检测人脸、提取身份向量和建议分组。人物命名、确认、重新关联、删除人物以及已有的人物影集继续保留。自动分组始终是建议，不能替代人工确认。

## 日常操作

- 进入人物页不会自动上传照片、下载模型或启动分析。
- 模型缺失时沿用主动下载入口；文件校验未通过时显示「修复本地人脸模型」。修复完成后仍由你主动点击分析。
- 已经分析过的照片、人脸关联和零人脸结果继续保留；更新模型不自动重扫、覆盖确认或改写影集成员。
- 较早版本没有完整模型来源的记录保持可查看、命名、确认和打开影集。新分析可能产生待确认候选；把候选关联到原有人物后，系统会保存该人物在当前模型下的参考向量，后续照片可以继续归组。
- 删除人物仍只移除人物及其参考关系，人脸回到待确认列表；原始照片保留。人物影集继续采用既有快照语义。

## 为什么需要区分模型来源

身份向量是模型对一张人脸的数值表示。把向量归一化后，当前引擎通过点积计算余弦相似度，达到阈值后提出同一人物的分组建议。

两个模型即使都输出 128 个数，也不意味着数值使用同一坐标系。模型权重、对齐和图像处理方法变化后，直接比较可能误归组。因此现在用模型名称、检测器 / 识别器 SHA-256、处理流程版本和维数构成完整模型空间；只有同一空间与维数的参考向量参与自动比较。

当前引擎保留已配置的 YuNet 与 SFace，使用固定权重校验、对齐、RGB / BGR 转换、最长边 1200 的输入及归一化 float32 向量。文件校验结果按文件身份和变更信息缓存；文件改变后重新检查，并在必要时重建引擎。分析前后检测到权重或流程改变时不发布结果。未核验来源的旧向量保留原字节，不猜测其真实模型，也不自动提升为已核验记录。

这里的「已核验」只描述模型来源与结构通过检查，不表示人物识别一定正确，也不等于用户已经确认身份。

## 数据保护与兼容

SQLite schema **12** 引入模型空间和按人物 / 空间保存的参考向量，为人脸观察记录增加来源；后续[人物整理](person-management.md)及[连续切图保存基础](seamless-split.md)使当前版本为 **16**，浏览器清单为 **12**。升级先备份；备份失败不改写数据库，重复升级保持幂等。旧人物 ID、名称、确认状态、关联影集、分析缓存及原有代表向量保留。

同一个人物可以保留不同空间的参考向量；主动重新关联后，只更新相应空间的参考关系，避免空分组继续招回已移出的脸。库复制保留来源，库合并验证空间标识、映射人物关系并优先保留目标库已有参考。原片不写入、删除或移动。

识别过程不在长时间图像计算期间占用写事务；保存前重新检查照片来源、已有人工关联、取消状态和模型来源。无效维数、非有限数、零向量或错误位置拒绝保存；取消、迟到分析或来源变化不会覆盖中途确认的人物。

独立网页 manifest 仍为 **10**，继续保留现有能力边界；本轮没有增加网页版人脸引擎、替换为 Mac CoreML / ArcFace，或新增云端人脸接口。开源权重的主动下载与本地推理分开，分析照片本身不访问国外 API。

## 验证范围

使用隔离合成图库和受控向量验证不同模型 / 未核验旧向量不混用、人工关联后继续归组、模型变化不覆盖旧确认、影集快照、取消与并发确认、错误向量、旧库升级失败回退、复制 / 合并、文件完整性、引擎缓存更新和原片 SHA-256。界面验证覆盖中文深色宽屏和英文浅色窄屏，修复与分析均需显式操作。

这些测试证明数据关系与流程保护；受控向量、模拟权重和模型修复响应不作为真实人脸识别准确率、跨年龄 / 姿态质量或真实模型性能证据。完整结果见[融合实施报告](afterframe-upgrade.md)，真实模型与正式安装包另行验收。
