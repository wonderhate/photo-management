# 桌面共享暗房与按需高清预览

对应 `codex/afterframe-upgrade` 当前开发工作树，尚未发布新的安装包。现有原片浏览、摄影空间、主题和水印引擎继续保留；全部融合进度见 [实施记录](afterframe-upgrade.md)。

## 使用

Windows 与本机后端网页现在可从附属导航的「创作工具」、已选照片的「光影暗房」，或原查看器的「编辑照片」进入暗房。`/tools/darkroom`、旧 `/tools/analyze`、`/tools/raw`、`/tools/edit` 深链接均可直接刷新。独立浏览器版仍使用对应 hash 链接。

暗房复用原来的 v1 参数算法、16 位线性 RAW 解码、直方图、Lab 仿色、曲线/HSL、归一化裁剪与 90° 旋转、基础锐化/降噪、100 状态参数撤销。保存编辑与导出分开：保存不会烘焙掉工程，最终 JPG/PNG 为 8 位 sRGB，不代表全程无损浮点显影。输入上限仍为 256 MiB、1 亿像素；实际可用大小取决于设备内存和格式支持。

编辑源另有独立版本：新工程识别缺少 EXIF 的 JPEG 内嵌 XMP 方向，并保存不可变解码规则；旧工程继续其原有输入。规则、升级备份和未覆盖入口见 [编辑源解码版本](source-decoding.md)。

两端像素与配方内核现统一在 `frontend/src/core/editing.ts`，浏览器旧入口保留兼容转发；算法与既有配方语义不变。浏览器保存关联原片的工程时，重新读取当前目录文件核对 SHA-256；即使页面仍缓存旧 File，也不能把旧配方保存到已被外部改动的来源。工程的独立快照仍按自己的哈希核验。

桌面编辑记录保存源文件的独立只读快照和 SHA-256。移出原照片记录后仍能恢复工程；参数更新检查 revision，其他窗口已经保存时拒绝覆盖。删除没有作品引用的编辑记录只移除记录，暂不清理其源快照。有已保存副本引用时阻止删除工程。

「另存并下载」保留 Worker 编码结果的原始字节，写入 exports，重名自动编号。「送入水印」先保存当前参数和独立渲染副本，再建立水印草稿；副本单独存放，不重复计入拍摄次数。暗房欢迎页可以重新找到编辑记录与已保存副本，每页加载 20 项。

桌面编辑副本送入水彩仍在适配，界面明确禁用并保留导出路径。独立浏览器原有的编辑副本送入水彩流程保持；进入工坊不自动调用云服务。几何构图、自由文字和分片来源已在后续批次接入；其余图层、深度遮挡及推理能力仍按实施记录推进。

## 自由文字与图层

暗房「文字与图层」可添加多行文字，并在画面上移动、缩放、旋转。支持本地字体、粗细、斜体、下划线 / 删除线、大小写、字距 / 行距 / 对齐、纯色 / 渐变填充及描边、四边背景、阴影与发光。17 种文字样式预设切换时重置上一种样式的效果，同时保留内容和位置；用现有授权字体替代远程字体。预设数值参考 AfterFrame 的 `textState.js`（固定版本 `26e19935469e696133088b798f23b5b3654d910f`），其 [MIT 版权与许可](../frontend/public/licenses/AfterFrame-MIT.txt)随前端发行文件保留。

图层列表支持选择、复制图层、复制 / 粘贴、排序、隐藏、锁定和删除。一次拖动只产生一次撤销；Esc 撤回当前手势。可吸附画面中心及其他文字锚点，Alt 暂停吸附，Shift 使旋转按 15° 递进；方向键微调，Shift 加速。缩放和旋转手柄保持固定可点按大小，长文字越过照片边缘时仍留在画面内。锁定文字可解锁、显隐和复制，不能直接移动或修改样式。

编辑文字时暂用适合画面的显示比例，退出文字编辑可恢复照片缩放操作。复用原配色、七种本地授权字体与系统字体，wonder 仍是固定署名图案；不请求网络字体。缺字使用本机回退字体，罕见字符仍需检查预览，不能保证所有 Unicode 字形均可显示。

保存采用明确标识的 **EditRecipe v3**，内含独立版本的文字文档；原 v1 / v2 保持严格兼容。旧工程可继续打开；含文字的工程不能降成旧配方而静默丢字，清空文字后仍保留 v3。SQLite 升至 17，浏览器清单升至 13；升级前保留原数据库 / 清单，拒绝未来或被错误标记的格式。库复制、合并及输出引用也检查完整文字配方。

预览、PNG / JPG 输出及分图复用同一 Worker 绘制路径；先按父工程的完整画面排字，再映射到分图选区并整幅绘制，最后切片，避免接缝处重新排字。含文字的分图保存完整父配方；分片继续编辑从已经含文字的中性快照开始。输出冻结保存时的配方和版本，后续改字不会改变旧作品。网页版水印等工坊的来源记录保留这份配方；有输出引用时不能移除工程。

每工程最多 32 层、每层 8192 个 UTF-16 单位 / 128 行、合计 32768 单位；临时效果画布上限 1600 万像素 / 单边 16000，超限明确提示失败。最终图像沿用原来的像素及输入大小限制，不自动缩小来绕过限制。当前源码批次包含编辑、图层操作、存储与渲染四部分，完整验证结果以[实施记录](afterframe-upgrade.md)末尾为准。

## 纯色 / 渐变蒙层与混合顺序

「添加蒙层」会在当前图层顶部添加一层从底部覆盖 40% 的透明到黑色渐变。可以改为纯色，或设置 2–16 个渐变色标，每个色标都有位置、颜色和透明度；整层还有独立透明度。角度 0° 从左到右，90° 从上到下。覆盖范围可选顶部、底部、左侧、右侧，比例为 1%–100%。蒙层不改变程序主题配色，照片调整先处理照片，再按图层顺序合成。

文字与蒙层放在同一个列表，列表上方表示画面中的上层。选择蒙层后可复制、粘贴、上移 / 下移、显隐、锁定或删除；这些操作沿用同一撤销 / 重做历史。将蒙层移到文字上方会覆盖文字，移到文字下方则保留明亮文字。保存后撤销到添加图层之前仍可再次保存，保留新格式但清空相应图层；重做也保留。

首次添加蒙层时转换为 **EditRecipe v4**，其中 `layer_stack` 明确保存有序文字和蒙层，原 v3 文字文档不变。SQLite 18 / browser manifest 14 升级前备份；浏览器把原清单字节写入 `library.before-layer-stack-v14-…json`。读取、库复制 / 合并以及输出引用均校验完整结构，拒绝未来图层、重复 ID、未知字段和错误格式。不能把含蒙层工程降为 v3 后悄悄丢失蒙层。合计仍最多 32 层。

预览、导出与分图共用 Worker 的图层绘制。蒙层随当前照片内容区域计算覆盖，文字按原位置映射；即使普通裁切与分图选区不同，也不会把蒙层限制在旧裁切框里。分图先完整绘制母版，再切片，不逐片重置渐变；子工程以已含效果的中性快照开始。纯色和多色渐变混排已接入；贴纸、深度遮挡及 LUT 库分别属于后续条目，不能把当前文字 / 蒙层混排写成全部创作图层已经实现。当前批次的完整验证进度见[实施记录](afterframe-upgrade.md)。

## LUT 样式库

打开照片后展开「LUT 样式库」，导入 `.cube` 文件，或从文件夹中批量导入。导入会复制内容到当前图库，保留原文件；同一内容不重复保存。可搜索、收藏、查看最近使用，以及移出 / 恢复样式。移出列表不会删除旧工程依赖的副本。点击样式应用，再次点击取消；强度 0–100%，滑动作为一次撤销操作，保存后仍能撤销 / 重做和重开。

「全部」列表按收藏、最近使用、其他样式排列，每个样式只出现一次；此处最近使用取列表快照的前 12 个，刷新后更新位置，避免用方向键浏览时卡片突然跳动。「最近使用」筛选可查看其余使用记录。方向键按分组后的实际行列移动，也支持跨页。

右键样式卡片或点「⋯」可应用、收藏、取出原始 CUBE、修正输入类型、移出 / 恢复；具备有效关联来源的 Windows 样式还可定位源文件。菜单支持方向键、Home / End 和 Esc；关闭后可回到触发按钮。整批移出需确认，作用于当前图库全部已复制样式，不受当前搜索或分组筛选限制；整批恢复可撤回。两端均一次保存全部可见性状态，失败时保持原状态，不删除样式字节、改写工程或复制未使用的关联目录文件。

缩略图基于原图展示 100% 强度，在独立后台线程按可见行生成。每页最多 40 项（三列时按整行显示 39 项）、缓存上限 64 项、最长边 280 像素；关闭面板释放线程与图片地址。实际编辑线程保留一个已解析色表，强度调整不重复读取色表。大型表格不嵌入每份撤销历史。

支持 UTF-8 `.cube` 的 3D 网格（2–65），单文件至多 32 MiB，读取 `DOMAIN_MIN/MAX` 或 `LUT_3D_INPUT_RANGE`。两种范围同时声明、重复关键头、缺行 / 多行、坏数值、1D / shaper 组合明确拒绝。节点允许超出 0–1，插值和强度混合后才限制最终输出；不提前裁掉色表范围。实现选用四面体插值，每个像素读取四个顶点，与参考仓库一致。

LUT 应用于照片调整后的 **sRGB 编码、8 位 RGB**，保留透明通道；随后绘制文字与蒙层。RAW 仍先用现有 16 位显影流程得到照片像素，再走相同 LUT 管线。连续分图先处理整幅母版，不逐片开始；子工程使用已经完成调色的分片，以中性参数打开。这里没有自动把照片转换成 Log，也不保证面向特定相机 Log / HDR 的 LUT 适用于当前照片。

首次应用 LUT 时工程使用配方 v5，其中只记录 LUT 内容 hash、强度和输入约定，原有调色、构图与图层参数继续保留。SQLite 19 把原始 CUBE 字节保存在 `lut_assets` 表，复制、备份及合并携带原字节；独立浏览器 manifest 15 保存元数据，字节位于 `drafts/luts/<hash>.cube`，完整图库备份包含它。首次升级先备份旧格式，备份失败不发布新记录；旧格式冒用新配方、未来格式、缺失引用或被修改的源文件均拒绝继续渲染，不默默略过效果。保存配方后，撤销到没有 LUT 的状态仍保持新格式。

列表提供 1 / 2 / 3 列显示、「隐藏 Log 样式」及原有分组筛选，并按当前图库记忆。Log 提示参考文件名称与标题中的输入曲线，避免把输出端名称和普通 Vlog 风格当成 Log；每个样式可指定「自动提示 / Log / 普通照片」。人工标识按内容 hash 独立保存，不会修改 CUBE 字节或已有工程。此标识只帮助选择样式，不启用自动颜色空间转换。关联目录中的路径和输入注释也参与辅助识别。

聚焦样式卡片后，方向键按当前可见顺序和列数浏览，可跨页，连续切换停下 700ms 后记为一次撤销；在停下前按 Esc 撤回整个序列。搜索框、滑块和选单仍使用原本的方向键。最近使用只记录最后确认的样式。调整强度完成后记忆到当前图库，下次在没有 LUT 的照片上选择样式时使用该值，已有工程保留自己的强度。

「按住对比 LUT」可用鼠标或空格 / Enter 按住，只临时去掉 LUT，保留曝光、其他调色、构图、文字和蒙层；松开、失焦或窗口隐藏时恢复。对比不增加撤销记录、不把工程标为未保存，也不会替换导出配方；按住时保存 / 导出操作不可触发。

「关联样式目录」通过系统目录选择器登记只读来源；目录树可按子目录筛选样式，展开状态随图库记忆。窗口重新获得焦点后延迟 750ms 扫描，也可手动扫描。目录失联或权限失效时保留目录记录和旧工程副本，使用「重新定位 / 授权」明确选择来源；「断开关联」只移除关联，不删除任何外部文件或已保存版本。

目录扫描限定 20 个来源，每个来源最多 5000 个 CUBE 文件、8 层子目录，每个文件最多 32 MiB。首次扫描读取完整字节计算内容 hash，只解析前 64 KiB 的头部；后续按大小和修改时间复用有效记录。桌面还检查文件身份并跳过链接、隐藏项及图库内部目录。缩略图直接读取源文件并核对 hash，不保存副本；应用、收藏或保存时完整解析并保存不可变版本，源文件变化时旧工程继续读取旧版本。目录或图库在操作中切换时拒绝发布迟到结果。首次扫描大目录仍需要磁盘读取时间，不能称为仅头部 IO 或实时文件系统监听。

当前 SQLite 21 / browser manifest 17 保存目录记录，升级前备份原数据。浏览器目录权限句柄保存在本浏览器的 IndexedDB；备份包含目录描述和已保存样式，换浏览器或设备需重新授权外部目录。外部目录的全部未使用文件不被完整图库备份自动复制。「导入文件夹」会复制有效 CUBE 并保留所选根目录和子目录层级；文件实际仍按内容 hash 保存，目录层级只是显示信息，不作为落盘路径。已复制样式显示在独立目录树中，可按子目录筛选，并记住展开状态。直接选择单个文件时，浏览器没有提供父目录路径，样式归入已复制样式根目录。

输入注释和目录信息随 LUT 元数据 v2 一起保存，断开外部目录关联后仍可提供 Log 提示。重导入相同内容保留首次登记的名称、分组、收藏和最近使用状态，恢复已移出的项目；旧 v1 样式仍可读取，显式重导入时补充来源信息。新来源元数据需要 SQLite 21 / browser manifest 17，升级前保留旧数据。

批量导入分别显示新增、已存在、已恢复、失败和非 CUBE 文件数量，失败项列出具体名称与原因；一个文件失败不撤销已成功导入的文件。每批最多 5000 个 CUBE，错误详情最多显示前 100 项。文件之间让出界面执行时间，选择相同目录再次导入不会重复保存字节。具体本批验证结果见[融合实施记录](afterframe-upgrade.md)。

可以直接将 CUBE 文件或目录拖入 LUT 面板。目录先完整枚举，再开始导入，保留目录层级；超过 5000 个 CUBE、20000 个总条目或 8 层子目录会停止本次枚举并提示分批选择，枚举中关闭页面不继续导入。单文件解析失败仍按上述汇总处理。目录树支持「展开全部目录 / 收起全部目录」，操作后仍可单独切换一个目录；当前状态随图库保存。目录很多时按页显示，所有树合计每页最多 240 个子目录节点，另保留至多 21 个根节点；「上一页目录 / 下一页目录」可访问其余目录，避免全部展开时一次挂载大量界面节点。统计页数仍需遍历已展开的目录，不把这项优化描述为恒定时间。

选中样式后显示文件名、网格大小、大小、分组和已保存输入注释。「取出 CUBE 文件」下载该版本的原始字节副本；若来自尚未复制的外部目录，会先保留该版本。Windows 的「定位关联源文件」只打开已登记且内容和扫描状态均未改变的源位置；已解除关联或文件变化时拒绝定位。纯浏览器提供文件取出，不模拟系统文件管理器。托管样式仍使用内容寻址存储，不暴露可编辑的数据库内部文件。

缩略图仍由独立单个 Worker 处理。离开可见范围时取消尚未开始的读取；已经开始的读取完成后若无人使用，立即释放结果。相同样式共用任务，最多保留 64 份闲置结果，可见图片引用受保护；切换照片或关闭面板释放整个预览队列。失败显示局部原因和「重试缩略图」，点击后重新读取，不改变编辑参数。线程启动失败或超时也允许重试；没有将这项优化等同于参考实现的多线程性能。

缩略图按设备能力使用 1、2 或最多 4 个独立工作线程，只为可见项目启动；进行中的 CUBE 源文件合计最多 32 MiB，完成结果缓存最多 64 张，正在显示的结果受保护。32 MiB 是读取输入量限制，不是整个程序的内存上限；解析字符串、像素和线程仍需额外空间。一个线程失败不会取消其他线程，单次线程请求 30 秒无响应后终止故障线程，可手动重试；关闭面板释放全部缩略图线程。

编辑工作线程另外缓存最近四个已校验色表，仍逐次核对输入字节，内容变化时拒绝使用缓存。相同样式来回切换无需反复解析色表；缓存随编辑线程结束释放。预览先解码下一张图，再替换当前画面；过时的结果和错误不会覆盖最新选择。当前渲染失败时保留上一次完整画面，后续成功渲染清除对应错误提示。

收藏、最近使用、其他样式、已移出分组可以独立折叠或全部展开 / 收起；分组数量按搜索和筛选后的样式计算。折叠状态随图库保存，不改变当前调色或工程。折叠的卡片不挂载、不占分页名额，方向键跳过它们；分组标题保留，可用 Enter / 空格展开。目录树折叠与样式分组折叠分别保存。

完整分辨率的工作线程导出和分图主图调色支持分段并行。输出至少 800 万像素，设备至少 4 逻辑处理器 / 4 GiB 已知内存时使用 2 个子线程；至少 8 处理器 / 8 GiB 时使用 4 个。预览、小图及未知 / 较低内存设备继续在原编辑线程处理。每个子线程最多传输 4 MiB RGBA 段，总计最多 16 MiB 在途像素副本；这不包括原图、调整后像素、色表、图层合成和编码的内存。线程只执行 LUT 步骤，完成后释放，不代表整个渲染管线并行。

并行时原段留在编辑线程，只有长度正确的成功结果才替换该段。启动、通信或计算失败及 30 秒超时会停止分派新段，未完成段在原编辑线程补算一次，已成功的段不重复调色；不返回半成品。预览与导出继续采用相同插值、强度和图层顺序，原始照片不写入。这里描述共享浏览器渲染工作线程路径，不宣称 Python 服务的独立渲染器也采用此线程池。

## 原查看器中的高清预览

普通桌面宽屏查看器保留原来的标准预览，并增加「预览清晰度」：标准、最长边 4096、最长边 6144。小图不放大。原有极光、雪境、胶片列车和摄影氛围保持；展映播放与胶片模式期间暂停重解码，窄屏继续普通预览。

选择高清后等待当前照片稳定 300ms，才读取当前源文件并检查完整 SHA-256。RAW 使用与暗房相同的 LibRaw-WASM 1.6.0 全量 16 位线性解码；不是把已有 JPEG 预览放大。高清显示图为 8 位 JPEG；透明 PNG 沿用各运行时已有的显示底色（桌面白底、独立浏览器黑底），不改变原PNG和编辑导出。RAW 的显影观感可能与相机内嵌 JPEG 不同；不会更改编辑参数、原片或导出的来源。

同一时刻最多一个重解码 Worker。切图、关闭、隐藏页面或进入展映时取消旧需求；完成后终止 Worker，内存缓存仅保存显示 JPEG 的 Blob URL。缓存键包含版本、图库、源 ID/完整 hash 和档位；最多保留 12 项/48 MiB 闲置压缩文件，在用引用受保护。邻图只使用已有标准预览，不自动对相邻 RAW 做高清解码。该预算不等同于浏览器全部解码纹理或进程内存预算。

桌面 TIFF / HEIC / HEIF 现有可取消原生子进程高清回退，保留方向、ICC、透明度和原比例。持久 JPEG 由本地 IndexedDB 缓存，总计 64 项 / 256 MiB，按库和实际解码版本区分；命中前仍先读取当前源并校验完整 hash。失败继续显示标准预览，提供明确的本地重试；收藏或标签更新不会自动重试坏源。独立浏览器不调用此原生回退。外部目录持续监听仍在后续范围；内存命中按已登记 hash 使用。细节、缓存清理及验证边界见[分层显示与缓存](display-previews.md)。

## 存储与恢复

桌面 SQLite schema 当前为 21（工程和副本在 schema 2 加入，图库身份与视图偏好在 schema 3 加入，schema 4 区分源解码语义，schema 17 保护含自由文字的配方 v3，schema 18 保护文字 / 蒙层混排配方 v4，schema 19 保存 LUT 资产与配方 v5，schema 20 保存外部 LUT 目录关联，schema 21 保存 LUT 来源分组与输入注释），新库初始化也立即记录版本。升级前复制数据库，包括没有 DDL 的语义升级；版本和 DDL 放在事务中。幂等重启、未来版本拒绝、备份失败不升级与 DDL 失败回滚已有合成回归。

- `documents/edits/<storage-id>/source.<ext>`：工程源快照。
- `assets/variants/<storage-id>/image.jpg|png`：独立编辑副本。
- `EditDocument`：源 hash、参数、revision 与可选旧 Photo 关联。
- `AssetVariant`：真实输出 hash、尺寸、参数快照与工程 revision。
- `library_profile`：随数据库移动的稳定图库 ID 与图库浏览偏好。
- `document_view_preferences`：每份工程的缩放，与 recipe 和工程 revision 分开；删除工程时级联移除视图记录。

逻辑 ID 和不可变 storage-id 分开，合并发生 ID 冲突时不改错文件目录。旧照片、影集和草稿的 ID 保持。存储目录复制会携带这两个目录并转换路径；合并后仍引用保留的源库文件时，不能删除那个源库目录。完整可移植备份、跨库资产复制与垃圾回收还需要后续完成。

数据库备份接口仍只备份数据库；完整恢复需同时保留上述目录、imports、水彩海报、水印预览等托管文件。外部原片、模型和自定义导出另行保存。新代码能拒绝不支持的未来 schema，但不能让已经发布且没有版本拒绝逻辑的旧程序自动获得保护；回滚必须同时使用匹配版本的程序、旧库和旧配置备份。

## 本机与安全策略

服务仍仅允许本机访问。页面 CSP 不开放动态 JavaScript 执行；只有固定 `/raw-1.6.0/` 下四个脚本/WASM 文件使用解码器需要的例外，并设置跨源隔离头。没有开放远程文件路径或恢复配对服务。

原片/快照的 HTTP 读取按流限制大小，超过上限或取消会停止读取。所有实际检查使用 `.test-artifacts/` 合成图库和已登记 RAW 样例；没有上传私人照片、使用真实密钥或触发付费生成。

设置保存范围、旧设置迁移与关闭时的处理见 [图库与作品视图设置](workspace-preferences.md)。
