# 任务阶段、资源队列与恢复

此说明对应融合开发分支。Windows／本机后端与独立浏览器均已接入持久任务阶段、资源执行队列与恢复，本机 Chinese-CLIP 准备／索引也接入同一后台调度。交互式搜索等短请求仍使用既有模型锁，不能把后台队列视为整个进程或 GPU 的统一调度器。

## 整体任务和工作阶段

原 `/api/jobs`、单项读取、取消接口和导出结果继续可用。列表按整体任务显示，阶段按选中任务惰性读取，避免把同一工作重复计数。可以进入阶段详情，再返回整体任务。

| 工作 | 实际执行阶段 | 旧结果的兼容方式 |
| --- | --- | --- |
| 导入 | 扫描文件 → 校验与入库／分批生成预览 | 整体保留固定文件总数与入库计数；预览进度独立，不重复计算照片 |
| 水印批量导出 | 渲染与导出 | 整体与阶段指向相同已登记文件，不重复渲染或下载 |
| 单张水彩／标题 | 生成或标题阶段 | 整体保留原 artwork_id、suggestions、results |
| 批量水彩 | 批量生成 → 可选标题 | 整体的图像计数不被标题计数覆盖；标题错误仍附在对应作品结果 |
| 人物和模型下载 | 分析或下载阶段 | 沿用旧人物模型与分组流程，不在任务创建时自动下载 |
| Chinese-CLIP 准备和索引 | 准备语义模型 → 照片语义分析 | 原设置页加载入口和 AIStatus 保留，增加 job_id；只用缓存的请求仍禁止下载 |
| 导入后的语义索引更新 | 照片语义分析 | 复用已加载模型和有效向量；合并正在索引时到达的导入请求，不重复创建任务 |

阶段按工作阶段建立，不按每张照片建立一条任务。当前每个整体任务最多 16 个阶段，实际工作流通常 1–3 个。导入的入库与预览阶段在批次间交替执行，阶段按创建顺序显示。层级目前为整体／阶段两层；未实现通用任意深度 DAG 或跨库依赖调度。批次、等待状态和修复行为见[渐进导入](progressive-import.md)。

父任务和阶段保存创建时的图库身份。SQLite `JobRecord` JSON 与独立浏览器 `library.json.jobs` 扩展这些字段，不改变 schema 3 或浏览器清单版本，也不更改照片、编辑 recipe、作品版本或原片。独立浏览器接入导入扫描／入库、水印批量导出、单张水彩和标题；人物、模型下载和批量水彩仍沿用各运行时原有支持范围。

## 资源调度

本机任务按读取／入库、图像渲染、人物本地推理、云请求、模型下载五种资源排队，各资源当前并发为 1。不同资源可以并行，同类任务保持 FIFO；兼容的自定义执行器也通过同一资源门槛调度。阶段直接在所属任务的工作线程内执行，不递归排入同一个单线程执行器等待，避免父等子、子等资源的死锁。

等待任务保留在有界调度队列，只有获得名额的任务才进入执行器。全局最多容纳 64 个排队／执行中的整体任务；达到容量时给出提示。取消尚未开始的任务会移出等待队列并释放名额；运行中的任务仍需等到当前安全检查点释放资源。

独立浏览器按读取／入库、渲染、云请求三种资源执行，各为 1，整体容量同为 64。不同资源任务可并行，但导入分析、水印和海报共用一个图片 Worker，重图像操作实际串行，图片请求队列也有 64 项上限。取消排队的图片请求直接移除；取消正在处理的普通请求后，必须等旧 Worker 返回或超时才复用图像名额，丢弃旧返回，避免立即叠加另一张大图。导入预览另在一张图片完成后检查取消，可以保存当前图片，但仍复核图库作用域；后续图片不再开始。Worker 故障或 180 秒无响应时，仅重建该图片线程；取消或超时均不会重试云请求。

两个运行时的导入均只在生成一张预览期间借用 render 名额，每张结束释放给已经排队的导出，再排下一张预览。整体 io 名额保持；只允许 io → render 借用，避免资源循环等待。借用阶段不再次占用整体任务容量，等待状态与实际执行状态分别持久保存。

两个运行时的活动中心均可展开「资源队列」查看实际任务运行数与等待数。任务资源名额与图片线程名额是不同层次，取消任务释放后，旧解码可能仍在图片线程中收尾。当前本机 local-ai 统一约束人物分析与 Chinese-CLIP 后台准备／索引，自定义的原模型执行器同样经过资源门槛。Chinese-CLIP 准备从缓存检查／下载到加载均占用同一个 local-ai 名额，以保持模型状态顺序；这比在下载时释放推理名额更保守。单次下载和模型调用仍在安全边界响应取消，不强行中断第三方库内部执行。并发数量测试不能代替真实大库、设备内存或 GPU 压力验收。

## 取消和已完成结果

取消整体任务会标记正在执行的必要阶段。取消一个必要阶段，也停止整体任务后续阶段；界面明确说明此范围。阶段完成、请求返回、文件之间都有取消检查，扫描也在目录与分批文件处响应取消。

取消不删除已经完成的导出、水彩作品、已入库记录或原始照片。本机图像解码、外部 HTTP 请求或正在写入的单个作品可能要到下一个检查点才结束，期间显示「取消中」。独立浏览器取消状态立即持久保存，后续阶段不再开始；图片线程仍可能按上文规则收尾。原水彩逻辑仍会清理未保存成功的应用自有临时文件，不触碰外部原片。

Chinese-CLIP 在下载、加载、每张编码和向量提交之间检查取消。取消准备任务后迟到的模型不覆盖当前实例；取消索引保留已提交向量，下次明确加载或后续导入时复用有效向量。等待中的任务取消后，即使回调尚未运行，设置和能力状态也会恢复可操作；读取状态不会自动重建任务。队列满时，自动索引的排队失败只显示在模型状态，不把已完成导入改判失败。原有 FAISS 和 NumPy 查询语义保持。

独立浏览器任务捕获图库 ID、目录句柄、会话代次和选中记录快照，在每个异步结果和写入边界复核。元数据提交排队时也绑定原目录与代次，不能在新图库打开后改写全局图库引用。关闭图库先等待设置写入、保存取消状态，再清除本次会话云密钥、撤销媒体引用并返回选择页；不再依赖整页刷新来隔离旧任务。旧 Worker 迟到结果不写入新库。关闭时若持久保存失败，显示错误并保留当前图库供处理。

## 云请求和重启

每次本机千问调用在实际发出前先持久记录提交边界，取消检查与此边界共享锁。取消若在边界前生效，就不发送该请求；越过边界后，取消不能保证阻止服务执行或计费。记录区分 not_submitted／submitted／responded／unknown；responded 只代表收到了响应，不是收费确认。

一次请求结果不明会留下持续的不确定标记，后续请求返回也不会抹掉这个提示。任务摘要与详情不保存密钥、图片正文或 HTTP 请求正文。现有 API 独立凭证、去 EXIF/GPS、用户显式提交和不重试计费的行为不变。

独立浏览器仍先询问用户、清除图片元数据并分块传至配置的中转。发送执行指令 `submit` 前等待任务提交状态持久保存，并再次检查取消；在这段保存期间取消，不会向中转发送执行指令。已发送至中转的数据不能由任务取消撤回。任务的 unknown 标记保守表示提交边界附近结果需要核实，不是确已收费。云任务在读取原片后核对完整 SHA-256，不接受导入后内容已变化的原片，不因此自动开启连接或上传。

重启时原 queued／running 任务和未完成阶段标为 interrupted，已完成阶段和结果保留。可能已提交但没有确定响应的云请求标为 unknown；不会重新排队、上传或重发。当前本地任务也不自动续跑。用户需要根据已完成文件及对应任务错误决定后续操作。

这些字段是任务级恢复信息，尚未替代后续 M5 所需的完整计费请求账本、请求 ID 查询、逐次幂等键和计费状态核实；不能据此宣称真实账户或画质已验收。

## 历史与接口

可选[导入后人物分析](import-face-analysis.md)使用独立的 `faces-import` 本地推理任务，导入详情可跳转查看。关闭开关仅取消这些自动任务，不取消手动人物分析或已完成的导入；重启不自动重放。默认不开启，模型和队列不可用时保留正常导入。

本机保留最近 100 个已完成的整体任务及阶段；独立浏览器保留最近 30 组完成历史及尚在收尾的任务。正在排队／运行的任务不被历史清理移除。清理按整组任务记录进行，不留下孤立阶段，也不删除结果文件。活跃任务优先显示，最近列表最多 100 个整体任务。

- `GET /api/jobs?summary=true`：轻量整体摘要，不加载结果内容。
- `GET /api/jobs/<id>`：兼容原详情，也可读取阶段。
- `GET /api/jobs/<id>/children?page=1&page_size=20`：阶段摘要，默认范围可覆盖当前最多 16 阶段。
- `POST /api/jobs/<id>/cancel`：按上述必要阶段规则取消。
- `GET /api/tasks/resources`：当前运行时资源容量、运行和等待数量；独立浏览器在本地路由处理相同接口。

检查使用隔离合成库、可控同步事件和模拟服务，覆盖跨资源执行、资源上限、容量、立即取消、父子取消、保留文件、原片哈希、历史整组回收以及不自动提交的恢复行为。独立浏览器另外覆盖运行中取消后图像名额保留、同页切库隔离迟到 Worker、刷新保留已完成阶段与导出、持久提交边界取消以及源文件哈希不匹配时不连接云服务。
