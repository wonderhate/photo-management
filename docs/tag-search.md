# 标签搜索与大标签库（融合开发分支）

搜索框中的标签建议改为按需查询，最多返回 7 个匹配标签；相机、镜头、全文、文件名和本地语义等既有入口保留。人工维护过的标签优先，其余标签按稳定名称顺序排列。输入中文字、大小写不同的英文或 `%_` 等字面字符均可搜索。

点击建议限定照片的标签；清除临时条件继续保留当前影集范围。打开「筛选 → 标签」，可以搜索所有可选标签，每页 60 条，点击「更多选项」加载下一页。原来的多选、任一 / 全部、排除、缺失值、零计数已选项及关联计数继续使用，详见[筛选栏](photo-facets.md)与[检索范围](query-scope.md)。

## 本机服务

`GET /api/tags` 接受 `q`、`page`、`page_size` 和 `order=name|count|manual`，并沿用现有 QueryScope / 查询参数。搜索词最多 256 字符，每页 1–100 条；无效分页、排序及跨库范围拒绝查询。结果包含 `value`、当前范围中的 `count` 与 `user_count`，以及总照片数、未设置照片数和是否还有下一页。

查询直接在现有 Tag / PhotoTag 和照片范围上分组、计数并分页，不读取原片。名称采用稳定 Unicode 顺序；`manual` 先显示范围内有人工作主关系的标签，再按名称排序，不随使用次数频繁跳动。删除标签关系、移出记录或修改来源后按当前数据重新计算。

为兼容既有调用，旧 `/filter-options` 默认行为保留；应用现在显式使用 `include_tags=false`，不再在页面初始化或每次修改后下载整份标签列表。摄影报告的镜头选项继续使用原有数据范围。

## 独立网页

后台线程按当前图库和版本建立可重建的倒排索引。索引仅接收照片 ID、当前有效标签及其来源，保存标签对应的照片与人工关系；不接收原片、原路径、完整 EXIF、AI 原始标注或密钥。查询只传当前范围的成员和有界搜索参数，返回当前页，避免每次在界面线程重复展开整份标签表。

同一图库版本复用索引；元数据版本变化后重新建立，关闭或重新打开图库会清理旧索引并拒绝旧请求。快速输入会取消旧查询，过期建议不能覆盖新文字。线程无法建立时使用本地元数据索引继续查询；加载失败和运行错误的恢复也保留数据身份与取消检查。

索引保存在内存，不作为权威数据写回清单，不进入备份或公开作品；标签索引本身不新增字段，[当前存储格式](seamless-split.md)为 SQLite schema **16** / browser manifest **11**。当前采用按版本重建，未宣称已经实现增量更新、持久化搜索索引或完整五万照片性能验收。

## 验证范围

使用隔离的合成图库测试一万余标签、稳定分页、人工 / AI 来源、字面搜索、影集内计数、元数据修改后的索引更新、关闭时取消及后台线程失败恢复。界面覆盖中文深色宽屏和英文浅色窄屏，使用当前主题与减少动态设置；原片 SHA-256 前后保持。完整回归和未完成事项记录在[融合实施报告](afterframe-upgrade.md)，不将这些检查作为真实 AI 标注质量证据。
