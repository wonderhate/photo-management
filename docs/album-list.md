# 影集列表：搜索、排序和重命名

本说明对应 AfterFrame 融合开发分支，适用于 Windows / 本机服务和独立本地网页版。这里整理的是逻辑影集，不改变磁盘目录、原片位置、影集成员或照片自己的手动顺序。

## 使用

- 在影集页搜索名称，支持中文及不区分大小写的子串匹配。「清除搜索」恢复当前列表。
- 选择「自定义顺序」「影集名称」「新建时间」或「照片数量」，使用箭头切换升降序；当前方向同时显示在图标及提示中。
- 自定义模式可拖动影集卡片上的点状手柄，也可使用上移 / 下移按钮。按钮支持键盘操作，适合窄屏。搜索后调整顺序也保留隐藏的影集。
- 新建普通、语义或条件集合后，清除当前搜索，切回自定义顺序，将新影集放到首位。之后仍可再次选择其他排序。
- 「重命名影集」只更新名称；名称不能为空，长度上限 120。重命名不改封面、成员、条件或语义匹配分数。条件集合同时保留「编辑条件」入口。

普通 / 人物影集与条件集合仍在原影集页，桌面原语义候选影集保留在智能影集页。两页共享当前图库的影集列表设置；浏览器不因此新增尚未支持的本地语义模型能力。原双击照片浏览器、摄影空间、悬停信息栏和全局主题 / 语言不变。

## 排序规则

| 排序 | 含义 |
| --- | --- |
| 自定义 | 按保存的完整影集 ID 顺序；新增但尚未编排的影集排在前面。调整搜索结果时，不用可见结果替换完整列表 |
| 名称 | 使用当前界面语言的自然比较；例如 Trip 2 在 Trip 10 前，大小写同级时以 ID 稳定排列 |
| 新建时间 | 按实际创建时间排序；重命名不改变创建时间。日期缺失时始终置后 |
| 照片数量 | 使用既有影集 API 的计数口径：桌面按拍摄分组，条件集合使用当前规则结果；同值以 ID 稳定排列 |

浏览器旧影集可能没有创建时间，不会根据打开或重命名时间补造历史。自定义顺序对缺少日期且未编排的旧影集保留原清单顺序；新创建的影集开始保存时间。照片列表里的评分 / 文件排序和影集内部的照片顺序均独立保留。

## 保存与兼容

排序字段、方向和自定义顺序随图库保存。搜索文字是当前页面的临时状态，不跟随图库迁移或发布。桌面复用 `library_profile.preferences.albums`，浏览器使用清单中的可选 `album_preferences`；AF16 的列表排序没有单独升级结构；AF17 总览加入卡片 / 表格偏好，AF17 当时为 SQLite schema 6 / browser manifest 5；AF24 多选筛选与 AF27 [本地人物模型保护](face-model-spaces.md)与[连续切图保存基础](seamless-split.md)使当前格式更新为 18 / 14，详见[影集总览](album-overview.md)。

设置在停止调整 350 ms 后合并写入。桌面通过图库身份检查和 SQLite 写事务更新独立命名空间，不覆盖图库布局或工具偏好。浏览器沿用目录对象、会话代次、revision 和元数据备份检查；即使关闭后重新打开同一 UUID，旧适配器也不能继续写入。复制 / 恢复保留设置，合并保留目标库的列表设置。

初始异步读取不能覆盖刚做的选择；离开再进入影集页时，等待此前已登记的设置写入，再恢复列表。写入失败时显示错误和重试入口，并保留该标签页中按图库隔离的临时记录，重新打开时恢复待保存字段。突然关闭浏览器或系统断电仍可能中断最后一次操作，临时记录不能代替图库备份。

设置仅允许四种排序、两个方向、卡片 / 表格模式和最多 10000 个唯一的有界 ID，不接受路径、凭证、图片参数或跨作用域字段。未知 / 损坏的浏览器设置拒绝覆盖清单。没有上传原片、调用 AI、下载模型或移动文件；原图删除保护继续由既有服务执行。

## 检查范围

验证覆盖自然名称、同值、缺失日期、过滤后编排、方向切换、新建置顶、重命名及空名称拒绝；普通 / 语义 / 条件三类的成员、封面和语义分数保持。另检查设置复制 / 合并、跨库 A–B–A、旧会话拒写、延迟初始化、失败恢复和快速离开 / 返回时的保存先后顺序。界面使用中文深色宽屏及英文浅色窄屏的实际浏览器流程，合成原片 SHA-256 不变。

最终完整回归数量和状态见[融合实施记录](afterframe-upgrade.md)。四图封面、日期跨度、表格及批量整理见[影集总览](album-overview.md)。
