# 小红书 Vercel＋Cloudflare 方案核查

核查日期：2026-10-16。适用项目：光影集 2.6.1 浏览器版。

**结论：可以用来低成本试运行网页，但不能据此保证国内稳定访问，也不能把现有完整 AI 中转直接迁入 Vercel 免费套餐。Cloudflare 在这篇方案里不是必需的。**

## 文章实际提出了什么

已读取 [这篇小红书的文字正文](https://xhslink.cn/o/7rzOnTW9i8L)。作者建议将网站部署到 Vercel，绑定自己的域名，把 DNS 交给 Cloudflare，并关闭代理，使用灰色云朵（DNS only）。作者将自己的访问测试概括为国内可以稳定使用。

下文核查这套组合的机制和限制；配图中的具体 DNS 值未逐项验证，不能直接照搬到你的域名。

## 哪些可行，哪些表述不准确

| 文章的做法或判断 | 核查结果 |
| --- | --- |
| 用 Vercel 托管网页 | 可行。光影集的纯浏览器构建可以作为静态网页托管，普通照片功能继续本地处理 |
| 用自有域名替代默认域名 | 有帮助，也是 Vercel 官方建议，但不能保证国内所有网络都可访问 |
| 换 Cloudflare DNS、关闭橙色云朵，就能加速国内访问 | 缺少依据。DNS only 不让网页流量经过 Cloudflare CDN，跨境访问问题仍可能存在 |
| DNS only 时去 Cloudflare 清网页缓存 | 对这条 DNS only 的网页流量无效；应检查浏览器、应用 Service Worker 与 Vercel 的缓存和部署 |
| DNS only 时设置 Cloudflare Full (strict) 来保障该网站 HTTPS | 该设置不参与这条直连流量。浏览器直接与 Vercel 建立 HTTPS，证书应在 Vercel 正确配置 |
| 必须把域名 DNS 搬到 Cloudflare | 不必。可以保留阿里云 DNS，按 Vercel 项目给出的记录接入 |
| 永久免费、无额外开销 | 不能这样承诺。有套餐用途与用量限制，域名续费、AI 调用及中转另算 |

### 核心区别：灰色云朵只解析地址

文章配置下，网页连接是：**浏览器 → Vercel**。Cloudflare 回答域名应该去哪里，网页内容不经过 Cloudflare 代理，因此它不为这条流量提供 CDN 缓存或网页加速。上述缓存与 SSL 判断是根据这条连接路径得出的。[Cloudflare 官方代理状态说明](https://developers.cloudflare.com/dns/proxy-status/)

自定义域名仍可能改善默认域名遇到的访问问题。但 Vercel 官方明确说明其没有大陆节点，大陆访问可能变慢或失败，表现随运营商与时间变化；自定义域名也不能消除这些问题。因此，作者的个人测试不能代替你面向国内和海外用户的验收。[Vercel 官方大陆访问说明](https://vercel.com/kb/guide/accessing-vercel-hosted-sites-from-mainland-china)

## 放到光影集上，能解决哪些需求

- **固定网址：可以。** 使用已有的 `photomanagement.online` 或其子域名，无需再购买域名。
- **照片与图库留在用户电脑：可以。** 复用现有浏览器目录授权和本地存储，部署包只包含公共程序、字体等资源。云端 AI 仍须在用户确认后发送本次处理图片。
- **减少后端存储和图片流量：可以。** 普通导入、整理和导出在本地执行；网页托管服务不承担照片图库存储。
- **接近 Windows 体验：仍需验证。** 托管平台主要影响下载、更新和联网功能，不能消除浏览器本身的权限、格式或性能差异。
- **国内与海外共同访问：可以作为候选，但尚未实测。** 不能把配置完成等同于两地所有用户都能稳定打开。

## 免费套餐和 AI 的两个边界

### 免费版有适用范围

Vercel Hobby 当前限定个人、非商业用途，并有用量限制。免费公开分享个人作品不等于自动成为商业用途；如果以后收费、接广告或用于商业业务，应按官方政策重新判断套餐。[Hobby 官方说明](https://vercel.com/docs/plans/hobby)

### 现有长任务不适合直接搬进 Hobby

截至核查时，Vercel 官方已说明 Functions 支持 WebSocket 公测，包括 FastAPI；不能再简单地以“不支持 WebSocket”否定它。但 Hobby 单次函数及连接最长为 **300 秒**，连接到时会关闭。[官方 WebSocket 说明](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)、[函数限制](https://vercel.com/docs/functions/limitations)

光影集现有 `cloud_relay/app.py` 的模型等待上限为 600 秒、完整请求上限为 880 秒。两者与 Hobby 的 300 秒上限不匹配。部分较快请求可能完成，也不能据此保证较慢生成安全完成；重连不会自动恢复现有模型请求，直接重发还可能重复计费。

因此，**网页可以放 Vercel，AI 继续使用单独的境外中转服务**，是复用当前实现的简单做法。若为了省服务器费而改造任务协议，需要另行设计和验证；不是照着这篇文章配置 DNS 就能完成的事情。

## 对你最合适的用法

如果想验证 Vercel 是否够用，可以先做一次独立的前端试验：

1. 保留域名在阿里云的现有管理和 DNS，不必为试验迁移到 Cloudflare。
2. 部署当前 2.6.1 浏览器静态构建，使用 `trial.photomanagement.online` 等测试子域名。
3. 在 Vercel 项目绑定该子域名，再到阿里云填写项目实际给出的 DNS 记录；不照抄文章里的固定 IP 或其他项目的目标值。[官方自定义域名接入流程](https://vercel.com/docs/domains/working-with-domains/add-a-domain)
4. 只用合成照片和独立测试图库，避免测试网址与以后正式网址的站点来源不同，影响真实图库的目录授权体验。
5. 国内用可获得的电信、联通、移动网络，海外用实际目标地区网络，跨几个时段检查首次完整加载、字体、刷新和目录功能。
6. 将相同前端在 EdgeOne 境外节点方案中的表现一并比较。两个方案都需要实测，不能预先保证其中一个在你的用户网络中更快。
7. 静态访问合格后，再选择正式托管平台并接入境外 AI 中转。模型密钥不写入网页或构建变量，不自动发起收费测试。

**Vercel 可作为免费的前端候选，但没有必要加上仅做 DNS 的 Cloudflare。** 原来的 EdgeOne 方案也按静态免费配额起步，所以改用 Vercel 并不会自动省掉 AI 中转费用。若保留现有长任务实现，之前计划的境外中转仍有用途。

本次只核查方案，未创建云项目、迁移 DNS、部署服务或调用收费模型。之前的 [境外部署方案](browser-global-deployment-plan-2026-10-16.md) 未因这次评估而自动切换。
