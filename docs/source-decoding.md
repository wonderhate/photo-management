# 编辑源解码版本与旧工程回放

此说明对应融合开发分支。参数 recipe 仍为 version 1；源像素规则独立保存，不通过修改旧 recipe 补偿方向。

## 工程合同

| 源规则 | 回放行为 |
| --- | --- |
| 没有 `decode_profile` 的旧图库照片 / 草稿 / 工程，或 version 1 | 沿用原有浏览器解码与 LibRaw 路径，额外方向恒为 1；无 EXIF 的嵌入 XMP 不改变输入 |
| version 2 新导入来源与独立打开的文件 | 原有解码基础上，仅为缺少显式 EXIF Orientation 的 JPEG 读取有效嵌入 XMP 方向；将额外方向 1–8 随源哈希保存 |
| RAW、PNG 等其他新源 | 此步骤额外方向为 1，继续原有格式解码，不把外部侧文件方向当作几何操作 |

`extra_orientation` 表示浏览器已有 EXIF 处理之后的额外变换，有显式 EXIF 时为 1，避免旋转两次。检测复用现有 exifr 和有大小 / 深度 / 节点上限的 XMP 解析，不读取外部侧文件的旋转。Worker 仍只保存一个源像素缓冲；裁剪、旋转、预览和最终导出都从这个缓冲计算。

新导入照片与独立打开的本机文件检测 version 2；图库进入暗房时继承照片规则，包括没有该字段的旧照片所对应的 version 1。重新打开已保存工程使用其不可变规则。参数保存只能更新 recipe / revision，不能静默替换源规则。桌面副本记录一并保存相同规则；复制、迁移和 ID 冲突合并保留它。源文件或快照哈希变化仍拒绝保存 / 回放。

浏览器标准预览、高清、直接水印导出、公开 JPEG 和用户确认后的云请求预处理均使用照片的规则。水印草稿保存创建时的来源快照，重开 / 修改 / 导出继续使用快照中的规则，不借用后来照片的状态。重新扫描旧照片只延续原有去重 / 修复，不自动添加新方向。公开清单不包含这些内部规则、原路径、EXIF 或哈希。

高清内存请求键另含规则对象，持久缓存算法键区分规则版本与方向；旧键仍对应旧像素。RAW 不接受额外 JPEG 方向，遇到这种无效组合立即拒绝，不能无声忽略。

桌面返回 `pipeline_version: pc-edit-v1 | pc-edit-v2` 与 `decode_profile`，不表示参数算法改为 recipe version 2。不支持的规则版本、非法值、version 1 的非单位变换和额外字段均拒绝；不能悄悄回退为另一种输入。后续更改底层解码语义也须新增版本和兼容验证，不能直接重定义已保存的 version 2。

## 格式升级与备份

桌面 SQLite schema 当前为 **5**（条件集合升级）；来源规则引入于 schema 4，规则保存在已有 `source_json`，没有为旧工程补写旋转。即使没有新增 DDL，schema 3 → 4 也先使用 SQLite backup 保存旧数据库，再在事务内更新版本；备份失败时不升级。幂等重开不会再次升级 / 备份。具备未来 schema 检查的旧版程序会拒绝新库；更早未实现检查的发布版仍须使用匹配程序和旧库备份回滚，不能混用。

独立浏览器当前新建库为 manifest **version 4**（条件集合升级）；来源规则引入于 version 3，区分图库照片及草稿的来源规则。现有 version 1 / 2 可读，第一次写入先保留原始字节的 `library.before-source-v3-<uuid>.json`，再发布当前 version 4；此备份独立于不断更新的 `library.previous.json`，以前的 v2 升级备份也保留。从 1 / 2 / 3 到 4 的首次写入另留 `library.before-rules-v4-<uuid>.json`，详见 [条件集合](rule-collections.md)。升级不改照片和旧 recipe。旧 version 1 / 2 读器原本就严格检查格式，会拒绝 version 3；新读器也拒绝伪装在旧格式中的新来源规则或未知未来版本。完整图库备份保留当前 manifest 中的规则和工程源快照；升级前的根目录元数据备份另留在原图库目录。

## 当前证据与边界

同一合成 JPEG 的新工程为 480×640、旧工程为 640×480；相同半幅裁剪分别得到 240×640 和 320×480。实际界面、重开、PNG 导出、四角色块像素、不可变源哈希、Native 副本 / 复制 / 合并、浏览器完整备份和旧清单升级原始字节均有回归。不支持的工程版本不会覆盖原清单。

新 JPEG 的图库标准 / 高清、水印与公开导出通过同一四角色块、实际尺寸和像素核对；旧图库及旧草稿经过重扫、导出和格式升级后保持旧方向，旧图库进入暗房也保持一致。坏照片规则、坏草稿规则、旧格式夹带新规则和未来清单均被拒绝，原清单不被覆盖。专门元数据刷新 / 目录监听、真实 WebView / 设备、更多完整机型和正式发行继续分别验收。
