# 留用、排除与清除选片标记

此功能属于 AfterFrame 融合开发分支，适用于 Windows / 本机服务与独立本地网页版。选片标记独立于收藏、星级、颜色和标签；「排除」只记录选择，不删除照片、手动影集关系或原片。

## 操作

在照片信息面板选择「留用」「排除」「清除标记」。照片卡片显示对应小旗图标，文字提示和不同形状分别说明状态。原查看器、悬停信息栏、摄影空间和现有配色沿用已有界面。

| 按键 | 操作 |
| --- | --- |
| P | 将当前照片或图库所选照片标为留用 |
| X | 将当前照片或图库所选照片标为排除 |
| U | 清除选片标记，回到未标记；评分、收藏、颜色等保留 |
| Shift + P / X / U | 标记后前进到当前顺序的下一张；图库需要单选，查看器使用当前照片 |

这些动作接入既有快捷键设置和照片操作菜单，可以重绑定；照片信息按钮提示随绑定更新。输入框、下拉框、编辑器和其他弹窗不会触发选片快捷键。按住按键不重复提交；保存期间选片动作暂时停用。

Shift 前进只在保存成功后发生，末尾不循环。图库中的下一张会成为新的单选并进入可见区域，键盘焦点随之移动；四种布局都保留有限渲染窗口。标记导致照片离开当前筛选时，从变更前顺序确定下一张；普通标记离开范围时关闭该照片查看器并移除失效选中。

保存期间如果换图、关闭重开查看器、打开其他弹窗、改变筛选或排序，旧操作不能再替新视图前进。保存失败时保留当前照片与选择，可重试。超过 10000 张的快捷批量操作分批保存；失败后明确提示已保存数量及未完成部分，不自动继续。

## 批量与筛选

在「批量编辑」选择标记，默认保持原标记。弹窗固定打开时选择的照片列表，后台标记完成或选中状态改变不会替换正在编辑的目标。它可以与评分、颜色和标签一起保存，各项互不替代。使用「清除标记」即可撤回排除，也可直接重新留用；原图无需恢复。

照片筛选增加「全部 / 留用 / 排除 / 未标记」。条件集合增加同名字段，支持等于、不等于、多个状态、NOT 和现有分组逻辑；成员及计数随标记改变。图库、ID 列表、统计与集合复用同一筛选口径。未使用选片条件的普通图库只更新当前缓存，不因每次标记重新拉取全库 ID；条件范围变化时仍查询当前结果。时间线查看器使用自己的顺序，返回时间线后标记图标同步刷新，不套用之前图库中的筛选。未标记是明确状态，不等于未评分。

## 数据与兼容

下述为 AF20 引入的结构；后续[人工描述与标签来源](photo-annotations.md)及[多选筛选](photo-facets.md)与[本地人物模型保护](face-model-spaces.md)及[人物整理](person-management.md)及[连续切图保存基础](seamless-split.md)使当前格式更新为 SQLite 21 / manifest 17，选片三态继续保留。

桌面 SQLite schema **8** 增加 `photos.flag`，旧记录默认 `unmarked`。合法值为 `picked`、`rejected`、`unmarked`；更新 API 同时接受显式 NULL 清除，并保存为 unmarked。升级前备份，重复迁移不改已有标记。新 RAW / JPEG 加入已有配对时继承对应记录的标记，不改收藏或评分。图库合并保留目标记录的标记，新照片保留来源标记，旧来源库的新照片补未标记。

浏览器 manifest **7** 增加可选 flag，读取旧 1–6 格式时仅在 API 输出中按未标记处理，不修改旧清单。首次写入前把旧 `library.json` 的完整原始字节保存为 `library.before-flags-v7-*.json`；备份失败不发布新清单。未知未来版本、无效 / NULL 状态以及将新标记或条件字段标成旧格式时拒绝覆盖。

标记不从外部 XMP 的负评分猜测产生，也不写回照片或 XMP。旧照片、草稿、解码规则和原始文件保持既有来源关系。两端 API 仍受图库身份、会话和 revision 约束。

## 检查范围

共享 PhotoQuery 向量核对 Python SQL 与浏览器对三态、旧缺省、NOT 和多值的处理。合成原片检查单图 / 批量标记、清除、筛选计数、动态集合、非法值、备份失败、迁移幂等与 SHA-256；另有中英文实际界面验证、失败不前进、关闭重开后的迟到操作及四种布局边界前进。大型滚动检查使用合成元数据目录，不作原片解码性能证明。

当前验证结果见[融合实施记录](afterframe-upgrade.md)。这是本地整理功能，不调用 AI 或上传照片。
