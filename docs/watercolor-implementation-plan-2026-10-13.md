# 水彩转绘实现计划

日期：2026-10-13。分支：`codex/ai-watercolor`。基于 Windows 2.4.0 的 `46f16e7`，沿用已移除 Android、配对和远程访问的代码。

本次只完成分支和实现规划，尚未修改应用功能或调用付费图像服务。

## 参考内容与暂定目标

用户参考：[创建水彩转绘技能](https://chatgpt.com/c/6ac7644a-4fdc-83ec-82f9-292c6336f7af)。对话读取接口返回不可用，当前浏览器也无法访问该对话。因此，下列水彩特征是暂定设计，不能视为已复现参考效果；具体提示词、样图和预设需要与参考对齐。

暂定目标：尽量保留照片主体、人物身份、构图与原始宽高比，呈现透明叠色、颜料晕染、自然留白和纸张肌理。人物、建筑和风景均能使用。人物脸部及建筑结构是否保留，需要通过样片判断，不能用提示词保证完全一致。

建议以 AI 图像编辑完成转绘，再用本地处理调节纸纹、色彩与输出。AI 负责重新组织笔触；本地处理负责生成后可以立即调整的效果。先做完整的单图流程。

## 用户操作与界面

流程：照片详情 → 水彩转绘 → 选择风格与设置 → 生成 → 原图/作品对比 → 保存作品 → 导出或送入水印工坊。

- 在照片详情增加「水彩转绘」，侧边栏增加同名入口；进入后可从照片库选图。
- 页面分为大幅画布、右侧设置区和底部作品操作，沿用现有浅色分区、留白、图标与字体。窄屏本机网页改为上下布局。
- 支持原图/作品切换和对比滑杆；生成前展示原图，生成后展示实际结果。
- 初步候选预设为「清透淡彩」「湿画晕染」「钢笔淡彩」，最终名称和风格由参考效果决定。
- 首版保留少量控件：风格、水彩程度、细节倾向、纸纹强度、输出质量和补充描述。水彩程度与细节倾向转换为提示词，不假设模型存在同名参数。
- 只有点击「生成」或「重新生成」才提交 AI 请求；纸纹和色彩微调在本地执行，预览与导出使用同一份设置。
- 任务显示排队、上传、等待生成、处理结果、完成或失败。无法取得真实模型进度时显示阶段状态。
- 每次重新生成保留前一版；「作品」页签可查看、命名、导出和删除已有结果。

## AI 接入建议

先接通一个图像编辑服务。建议以 OpenAI Images API 的 `POST /v1/images/edits` 作为首个验证对象，使用原照片和固定的水彩提示词。接口支持输入图片与文字描述；`gpt-image-2` 是可验证的候选，模型选择以账户可用性和样片结果为准。[OpenAI Docs：图像编辑接口](https://developers.openai.com/api/reference/python/resources/images/methods/edit)

- 利用已有 `httpx` 发起请求，首版不增加通用供应商框架或新的 SDK。以后接其他服务时按其真实图像编辑协议增加支持。
- 图像转绘配置与现有 Chinese-CLIP 检索模型配置分开。当前检索功能不能直接承担图片转绘。
- 先提供 API Key、模型、质量和连接状态设置；默认使用官方 HTTPS 地址。
- Key 仅在后端使用。Windows 保存凭证时使用系统保护能力，例如 DPAPI；源码/容器可读取环境变量。设置查询只返回「已配置」及遮罩，凭证不进入前端持久存储、数据库作品记录、日志或发行包。
- 上传前通过现有 `open_image` 读取并处理方向和色彩，另存不含 EXIF/GPS 的临时输入；RAW 先解码为模型支持的图像。原文件始终只读。
- 提交前明确显示上传图片的服务和生成张数，默认一次一张。未配置服务时可以查看作品与编辑本地设置。
- 输入、输出尺寸按模型约束处理。GPT Image 2 的宽高需符合接口限制；超长比例使用明确的留边方案，避免拉伸或未经选择裁切主体。导出显示真实像素尺寸，放大另标为放大。[OpenAI Docs：尺寸约束](https://developers.openai.com/api/reference/python/resources/images/methods/edit)
- 不把随机种子、精确转绘强度或百分之百人物锁定作为通用能力。保存模型、提示词版本及设置便于追溯，但再次请求可能产生不同结果。
- 展示耗时和生成次数；服务返回用量时再记录用量。费用以实际服务账单为准，不把未知用量显示为零。
- 超时后保留任务信息并由用户决定是否重试，避免自动重复提交可能已经计费的请求。
- 取消采用协作方式：阻止尚未提交和后续处理，已送达云端的生成可能继续执行或计费。程序重启将未完成任务标为中断，不自动重新生成。

## 与现有代码衔接

| 位置 | 复用与新增内容 |
|---|---|
| `frontend/src/App.tsx`、现有导航状态与 `i18n.ts` | 增加入口、照片传递和中英文文字 |
| 新增 `frontend/src/ArtPage.tsx` | 转绘画布、少量参数、任务状态及作品页签；样式沿用 `archive.css` |
| 新增 `backend/app/art_routes.py`、`art_schemas.py` | 生成、作品列表/详情、设置、导出与删除接口，接入现有本机访问保护 |
| 新增 `backend/app/services/art_service.py` | 提示词预设、图像准备、HTTP 调用、结果校验、本地后处理与作品保存 |
| `backend/app/services/jobs.py` | 复用持久化、查询、取消和中断恢复；给 AI 请求一条独立工作线程，保留原有导入任务执行方式 |
| `backend/app/models.py`、`config.py`、`storage.py`、导入扫描逻辑 | 增加作品记录及派生目录，检查迁移、备份和扫描排除 |
| 现有水印草稿与渲染服务 | 增加作品来源关联，将水彩作品送入已有相框、环境光和署名流程 |

作品使用单独的 `artworks` 表，记录原照片关联及快照、风格与设置、提示词版本、服务/模型、任务标识、输出尺寸和派生文件位置。生成结果放在 `DATA/artworks/<id>/`，数据库使用相对库目录的路径；重新生成产生新作品记录。

作品不会自动登记为新的原始照片，照片数量、拍摄统计及 RAW/JPG 分组保持原有含义。需要加入照片库时由用户主动导入导出的作品。

现有 `WatermarkDraft` 的设置会被 `WatermarkOptions` 校验，不能直接把转绘参数塞入其中。水印阶段增加可空的作品来源关联，并让渲染服务从关联作品读取图像、从原照片快照取得拍摄信息；所有现有水印草稿仍走原流程。

导出继续使用用户设置的输出目录、已有文件名规则和 `export_registry`。新增派生目录必须从自动扫描中排除；修改照片库路径时检查作品文件及其关联迁移，明确现有数据库备份与图片文件备份的范围。

## 分阶段交付

| 阶段 | 实际工作 | 完成标准 |
|---|---|---|
| 1. 对齐效果 | 获取参考提示词/样图；用经用户选择的少量人像、风景、建筑样片比较风格，记录尺寸、耗时与服务用量 | 确认一种接近参考的默认风格；明确人物保留和细节变化的实际限制 |
| 2. 打通单图 | 图像服务配置、图片准备、单图请求、独立后台执行、原图/作品对比 | 从任一有效照片得到一张实际作品；界面保持可操作，失败可恢复 |
| 3. 作品管理 | 持久保存、命名、再生成版本、本地纸纹/色彩调整、JPG/PNG 导出 | 重启后作品可打开；调整本地效果不调用 AI；导出不会覆盖原图或同名文件 |
| 4. 连接水印 | 作品来源关联，接相框、环境光及中文/英文艺术字署名 | 水印预览与正式导出均使用水彩作品，拍摄信息来自原照片 |
| 5. 验证与打包 | 双语/明暗主题、失败与取消、库迁移、Windows 实际 EXE 和安装器 | 自动检查通过；用户库、原图和旧草稿保持完整 |

建议第一轮交付到阶段 3，再完成水印联动。批量生成、本地 GPU 模型、ComfyUI、局部蒙版和多服务切换，在单图效果及使用需求确认后再安排。

## 验证重点

- 视觉：横竖图构图、人脸与手部、建筑直线、颜料晕染、纸纹与留白；使用原图和实际生成图逐项比较。AI 效果必须人工看样片，模拟响应只能验证软件流程。
- 数据：生成、取消、删除作品、导出和加水印前后，测试原图 SHA-256 一致；原照片统计不增加；重启及库迁移后作品仍可读取。
- API：无凭证、鉴权失败、限流、断网、超时、空结果、无效图像和程序中断；任何错误日志均不泄露凭证。
- 界面：中英文、明暗主题、长文件名、窄屏布局、键盘操作、对比滑杆和任务提示；本地调整不产生额外图像请求。
- 分发：实际 Windows EXE 的生成到导出流程、安装升级后的作品与配置保留，以及发行包凭证/私图排除。

当前待对齐项：参考对话里的具体风格与提示词、首个可用的图像服务。它们影响阶段 1 的样片验证；上述应用结构和单图流程可以先作为实施方案讨论。
