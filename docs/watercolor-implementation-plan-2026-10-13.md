## 已明确的目标与参考

目标是「极简手绘水彩旅行海报」：完整原场景转绘、温暖象牙白纹理纸、细墨线、透明水彩、少量颜料沉积和自然不规则笔触边缘，插画下方居中放置准确的手写标题。保留原图主体数量、动作、朝向、服装颜色、位置关系、背景、透视与光照，不添加原图没有的人物、建筑或景物。AI 对上述内容的保留程度必须通过原图对照验证，不能承诺逐项完全一致。

参考图的插画视觉上约占纸面宽度 85%，大于文字要求的 50%–60%；这只是目测值。提供两种版式：「留白旅行海报」默认 55%，「参考图版式」约 85%。两者共享同一张转绘结果，本地切换即可。参考图中的竹筏、河流、山体和「漓江竹筏」标题不能迁移到无关照片；没有参考图对应的原照片，不能据此判断主体保留是否准确。

实现采用「AI 转绘完整场景 + 本地纸面排版 + 本地文字渲染」。最终纸张画布保持经方向校正后的原图宽高比；场景等比缩小，不裁切、不拉伸。「不扩图」解释为不生成原场景之外的新景物，纸面留白只属于排版。尺寸受模型限制时使用可追踪的输入留边，返回后仅移除已知留边；无法安全恢复时提示重新生成，不通过拉伸或裁掉主体修正。

## 转绘与标题流程

1. 选取原照片并读取方向、尺寸及必要 EXIF。用户可以直接填写最终标题，或填写关键词后主动点击「建议标题」。
2. 建议标题时使用单独的图像理解请求，结合画面内容和可用元数据生成少量候选，展示内容/地点依据。用户确认、编辑或选择不加标题后才进入正式转绘；改选照片会清除旧的确认状态。
3. AI 仅生成完整场景的水彩插画，不生成最终标题，不在场景内再嵌套一张海报。主色与光照来自原片，不强加日落或蓝紫桃色；原图本来存在的颜色与景物不能因为负面提示词而被删除。
4. 本地将插画等比置于象牙白纸上。画面下方留出标题区域，插画和标题整体在纸面上平衡居中；窄长画幅必要时缩小整体并显示实际占比，避免标题越界。自然水彩边缘由转绘体现，不用会擦掉边缘人物的椭圆遮罩或粗暴羽化制造留白。
5. 本地绘制用户确认的原文标题，优先复用现有中文手写字体 `LongCang`，提供已有字体选择与缺字回退。标题保持一行，过长时提示修改或缩小字号，不静默截断、改字。标题、字体、纸纹和版式修改均不重新调用图像服务。
6. 保存场景层、最终海报、预览和排版参数，允许稍后修改标题和版式再导出。

当前照片记录有拍摄时间、GPS 和原始 EXIF，但没有可直接使用的地点名称或现成地理编码服务。GPS 到地名需要单独的反向地理编码来源；没有可靠来源时只给画面内容标题，地点标为未知。仅凭视觉猜测的地点必须标为待确认，不能自动填成事实。首版可先使用用户输入的地点，地名自动解析作为独立可选能力；精确 GPS 不默认发送给图像服务，启用外部地点查询时需明确接收服务与所发数据。

图像编辑请求不负责返回结构化标题。候选标题可通过支持图像输入与文字输出的 Responses API 实现，沿用同一后端请求方式；具体视觉模型以账户可用性验证。手动填写标题可完全跳过这次请求。[OpenAI Docs：Responses API](https://developers.openai.com/api/reference/responses/overview)

## 用户操作与界面

流程：照片详情 → 水彩转绘 → 填写标题或获取建议并确认 → 选择版式 → 生成 → 对比完整场景与原图 → 微调排版 → 保存/导出。

- 在照片详情增加「水彩转绘」，侧边栏增加同名入口；进入后可从照片库选图。
- 页面分为大幅画布、右侧设置区和底部作品操作，沿用现有浅色分区、留白、图标与字体。窄屏本机网页改为上下布局。
- 支持原图、转绘场景和海报预览切换；对比滑杆使用尺寸对齐后的原图与场景层，避免把缩小的海报插画直接与满幅原图叠加。
- 首版固定「极简手绘水彩旅行海报」画风，先验证参考效果，再考虑新增风格。
- 首版控件：标题、标题建议/确认、字体、两种版式、纸纹强度、输出质量和补充描述。标题建议会独立调用 AI，按钮旁说明；改变画风描述或质量只影响下一次正式生成。
- 只有点击「建议标题」「生成」或「重新生成」才提交对应 AI 请求；排版设置在本地执行，预览与导出使用同一套渲染逻辑。
- 任务显示排队、上传、等待生成、处理结果、完成或失败。无法取得真实模型进度时显示阶段状态。
- 每次重新生成保留前一版；「作品」页签可查看、命名、导出和删除已有结果。
- 默认海报不加边框、阴影、印章或水印。只有用户主动选择「送入水印工坊」时才进入现有水印流程。

## AI 接入建议

先接通一个图像编辑服务。建议以 OpenAI Images API 的 `POST /v1/images/edits` 作为首个验证对象，使用原照片和固定的水彩提示词。接口支持输入图片与文字描述；`gpt-image-2` 是可验证的候选，模型选择以账户可用性和样片结果为准。[OpenAI Docs：图像编辑接口](https://developers.openai.com/api/reference/python/resources/images/methods/edit)

- 利用已有 `httpx` 发起请求，首版不增加通用供应商框架或新的 SDK。以后接其他服务时按其真实图像编辑协议增加支持。
- 图像转绘配置与现有 Chinese-CLIP 检索模型配置分开。当前检索功能不能直接承担图片转绘。
- 先提供 API Key、图像模型、标题建议模型、质量和连接状态设置；默认使用官方 HTTPS 地址。
- Key 仅在后端使用。Windows 保存凭证时使用系统保护能力，例如 DPAPI；源码/容器可读取环境变量。设置查询只返回「已配置」及遮罩，凭证不进入前端持久存储、数据库作品记录、日志或发行包。
- 上传前通过现有 `open_image` 读取并处理方向和色彩，另存不含 EXIF/GPS 的临时输入；RAW 先解码为模型支持的图像。原文件始终只读。
- 提交前明确显示上传图片的服务和生成张数，默认一次一张。未配置服务时可以查看作品与编辑本地设置。
- 默认只发送选中的原照片与提炼后的画风指令，不自动上传参考图。主提示词拆为场景转绘要求和本地排版要求；服务没有独立负面提示字段时，将约束写入普通提示词，不假设通用 `negative_prompt` 参数。
- 输入、输出尺寸按模型约束处理。GPT Image 2 的宽高需符合接口限制；超长比例使用明确的留边方案，避免拉伸或未经选择裁切主体。导出显示真实像素尺寸，放大另标为放大。[OpenAI Docs：尺寸约束](https://developers.openai.com/api/reference/python/resources/images/methods/edit)
- 不把随机种子、精确转绘强度或百分之百人物锁定作为通用能力。保存模型、提示词版本及设置便于追溯，但再次请求可能产生不同结果。
- 展示耗时和生成次数；服务返回用量时再记录用量。费用以实际服务账单为准，不把未知用量显示为零。
- 超时后保留任务信息并由用户决定是否重试，避免自动重复提交可能已经计费的请求。
- 取消采用协作方式：阻止尚未提交和后续处理，已送达云端的生成可能继续执行或计费。程序重启将未完成任务标为中断，不自动重新生成。

作品使用单独的 `artworks` 表，记录原照片关联及快照、风格与设置、提示词版本、服务/模型、任务标识、输出尺寸和派生文件位置，并保存已确认标题、标题依据、版式占比、字体与纸纹参数。生成结果放在 `DATA/artworks/<id>/`，分别保存场景层、海报和预览；数据库使用相对库目录的路径。重新生成产生新作品记录，本地排版修改复用场景层，不增加 AI 请求。

作品不会自动登记为新的原始照片，照片数量、拍摄统计及 RAW/JPG 分组保持原有含义。需要加入照片库时由用户主动导入导出的作品。

现有 `WatermarkDraft` 的设置会被 `WatermarkOptions` 校验，不能直接把转绘参数塞入其中。水印阶段增加可空的作品来源关联，并让渲染服务从关联作品读取图像、从原照片快照取得拍摄信息；所有现有水印草稿仍走原流程。

导出继续使用用户设置的输出目录、已有文件名规则和 `export_registry`。新增派生目录必须从自动扫描中排除；修改照片库路径时检查作品文件及其关联迁移，明确现有数据库备份与图片文件备份的范围。

## 验证重点

- 视觉：横竖图及超长比例，逐项比对主体数量、动作、朝向、服装颜色、边缘主体、背景、透视与光影；无凭空新增景物。检查细墨线、透明叠色、不规则边缘和纸纹，避免矩形卡片边界。AI 效果必须人工看样片，模拟响应只能验证软件流程。
- 排版：55% 与约 85% 版式复用同一场景；最终比例遵循原图（整数像素舍入除外）；场景不裁切、不拉伸；标题位于画面下方且准确、清晰，覆盖长中文、英文及缺字回退。不得为留白擦除主体。
- 标题：有/无 GPS、地点未知、视觉误判、手动关键词、直接输入、修改标题和换照片；候选不自动确认为事实，取消建议请求仍能手动继续。仅改本地标题、字体或版式时图像生成调用数不增加。
- 数据：生成、取消、删除作品、导出和加水印前后，测试原图 SHA-256 一致；原照片统计不增加；重启及库迁移后作品仍可读取。
- API：无凭证、鉴权失败、限流、断网、超时、空结果、无效图像和程序中断；任何错误日志均不泄露凭证。
- 界面：中英文、明暗主题、长文件名、窄屏布局、键盘操作、对比滑杆和任务提示；本地调整不产生额外图像请求。
- 分发：实际 Windows EXE 的生成到导出流程、安装升级后的作品与配置保留，以及发行包凭证/私图排除。

提示词和视觉方向已经明确。实施时仍需验证账户可用的图像/视觉模型，以及真实样片中主体保留与边缘处理的效果；当前规划不调用云端生成、不上传私人照片。
