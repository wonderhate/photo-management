# 公开作品展示模式

公开版直接展示已发布的照片，不要求访客授权本地目录。首页提供全幅封面、精选作品和相册系列；作品支持标题、说明、标签搜索；相册有独立链接；灯箱支持方向键、Escape、缩放、照片说明和缩略图。保留中英文、明暗主题、减少动态效果与窄屏布局。

## 选片和生成发布包

1. 在浏览器本地版打开自己的图库，进入首页底部的 **导出公开作品**。
2. 手动勾选允许公开的照片，填写网站名称、首页介绍、作品标题、说明和标签。默认不勾选任何照片，公开标题默认是“作品 N”，不会直接公开原文件名。
3. 调整照片顺序：前 12 张用于首页封面与精选。可勾选相册名称；相册只包含本次明确勾选的照片，即使原相册还有其他照片也不会导出。
4. 选择展示尺寸（1600/2048/2560/3840）和 JPG 质量（60–95），点击 **选择目录并导出公开内容**，选择与原片、图库分开的目录。
5. 工具创建一个新的 `Lumina-public-日期-随机标识` 文件夹。复制它的完整路径，在项目根目录运行：

```powershell
npm run build:showcase -- --content "D:\发布内容\Lumina-public-实际文件夹名"
npm run preview:showcase
```

打开 http://127.0.0.1:4176/ 检查。将 `frontend/dist-showcase` 文件夹的**内容**上传静态托管，确保 `index.html` 位于网站根目录，并保留 `edgeone.json`、`portfolio`、`assets`、RAW 资源与许可证。构建和预览命令都不会自动上传或发布。

不带 `--content` 的 `npm run build:showcase` 生成空作品站点，用于检查部署与空状态，不会搜索或自动包含本机照片。常规 `npm run build:web` 仍输出原有本地图库版 `frontend/dist-web`；桌面构建仍为 `frontend/dist`。

公开站底部“本地图库”和“创作工具”通过 `?local=1` 进入原有本地工作流。它们访问的是该访客自己的本地图库，并不是网站作者的管理后台。完整目录功能仍需要桌面 Chrome/Edge、HTTPS 或 localhost；纯公开浏览不依赖目录访问 API。

## 派生作品选片

导出窗口可切换照片与暗房副本、水彩、拼图成品、切图面板。每种来源都需逐个明确勾选，默认不选中；选择派生作品不会连带导出其原片、工程或其它版本。公开图片仍重新编码为 JPEG，清单继续仅包含原有公开字段，不写入来源关系、地点记录、配方或图库 ID。访客本地图库入口及整包替换方式保持原样。

构建时再次按白名单重建清单，检查 JPEG 结构和完整性、长边不超过 8192 像素、单文件不超过 25 MiB，并移除 APP/COM 元数据段；不改变 JPEG 图像压缩数据。仅接受内容目录内的普通文件，构建前后复核来源哈希，拒绝构建期间变更的来源。

2026-10-26 与 AF06、AF64–AF69、PC18、PC22 共十项统一验收：公开展示 4 项通过；选定水彩导出、规则影集成员白名单及公开像素方向回归通过。带 EXIF 和私有字段的两张合成图经过实际构建后，仅选中资源进入包，私有字段及 EXIF 不存在，解码像素完全一致。没有部署到公网。

## 更新、下架与隐私边界

- 更新作品：重新选片、导出、构建，使用托管平台的新部署**替换整份旧发布包**。不要将新 `portfolio` 文件夹合并进旧目录，否则旧文件仍可能通过 URL 访问。
- 下架全部作品：不带内容重新构建空站，并替换旧部署。托管平台保留的旧部署、CDN 缓存需按平台规则撤下或清理。已经被访客下载的副本无法收回。
- 导出先校验来源哈希，再在 Worker 中重新编码 JPG，生成缩略图和长边受限的展示图；不会覆盖原片，不携带原片 EXIF/GPS。公开文件名由展示副本的 SHA-256 生成。
- 清单只包含网站文字、公开标题/说明/标签、展示尺寸、资源地址、相册关系与精选顺序，不包含原片路径、来源句柄、文件哈希、编辑历史、密钥或图库数据库。
- 图片画面本身及用户填写的公开文字会被访客看到。相册名称仅在勾选后导出。
- 失败或取消的导出不会写入最终 `portfolio/manifest.json`，因此无法被构建为有效发布包。可能留下未完成的独立文件夹，可自行移除；原片和图库不受影响。取消会在当前图片处理结束后的检查点停止。
- 构建脚本只复制清单引用的 JPG，不复制额外文件；校验路径、重复 ID、照片/相册关系、格式版本及数值范围，拒绝指向导出目录以外的资源。
- 公开照片和清单不进入 Service Worker 缓存。图片仍可能被浏览器 HTTP 缓存或托管平台缓存；作品清单使用 `no-store` 请求。这里不承诺公开作品离线浏览。

## 参考依据与实现取舍

参考 https://cn.chuweimin.com/ 的公开首页、系列作品入口与全部照片索引，沿用“大幅摄影封面 → 精选作品 → 系列相册 → 沉浸浏览”的结构。实际参考截图保留在忽略目录 `.test-artifacts/reference-desktop.png`、`reference-mobile.png`。没有复制参考站照片、品牌和个人经历。

复用了前次 REA 静态分析记录 `ev_0e9dd08ee6bf0265c304f29b74904832cd149c018a7dc4b2eb4a3f1ac5caf4b6`：React/Vite JavaScript 目标，非 PE/.NET；`AllPhotosPage-CgmSaO40.js` 中观察到系列、年份、器材、地点等筛选。该记录只分析了选定的 9 个 JavaScript 文件，关系覆盖为 partial，不能据此宣称已经验证参考站所有运行行为。本次标题/说明/标签搜索及本地导出为光影集的实现选择，不宣称复现参考站全部搜索功能。

本版使用同源静态清单 `portfolio/manifest.json`，无服务器 API、账户、远程管理或自动同步。每份清单上限 2000 张照片、200 个相册；精选最多 12 张。站点需部署在域名根路径。hash 路由方便静态托管刷新及照片直达，但不提供每张照片的独立服务端 SEO 页面。网站标题与介绍会写入构建后的 HTML。
