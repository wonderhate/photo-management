# RAW 入库与预览

此说明对应 AfterFrame 融合开发分支，正式安装包仍需单独发布与验收。

独立浏览器图库现在支持选择多个 RAW 文件或扫描已授权目录。文件选择保存原始字节副本；目录导入只保留只读原片关联。常见 DNG、CR2、CR3、NEF、ARW、RAF 等扩展名交给已安装的 `libraw-wasm@1.6.0`，实际相机和压缩格式支持取决于该解码器。扩展名可选不代表所有机型都能解码；损坏或不支持的文件单独失败，批次继续。

| 路径 | 图像来源与处理 | 保存内容 |
| --- | --- | --- |
| 批量登记 | 完整 SHA-256、exifr / LibRaw 元数据，不解码完整像素 | RAW 格式标记、完整源尺寸、器材、时间、方向与来源位置 |
| 图库浏览 | 优先嵌入 JPEG / 位图，无可用预览时完整 RAW 解码后缩小 | 最长边 480 / 1600 的独立 JPEG；记录嵌入图或完整解码来源 |
| 暗房 / 按需高清 | 始终读取完整 RAW；16 位线性 sRGB、相机白平衡、关闭自动提亮 | 保留原有编辑参数、源哈希和独立导出；不用嵌入 JPEG 代替编辑源 |
| 水印 / 公开展示图 | 完整 RAW 经同一 16 位源解码后生成显示像素，再交给现有布局 | 8 位 sRGB 派生文件；公开展示 JPEG 去除原始 EXIF |

图库预览可能体现相机内置 JPEG 的色调，与暗房的线性源显影不同。预览尺寸和 RAW 完整源尺寸分别处理，不拿嵌入小图的尺寸改写原片信息。LibRaw 1.6 返回的源尺寸已经按方向归一，不能再次交换宽高；嵌入 JPEG 自带 EXIF 时由浏览器处理，否则采用 RAW 方向。EXIF 数值字段保留数值，避免把「旋转 90 度」等显示文字当作方向值。

元数据先分批登记，预览随后通过现有资源队列生成，首批照片可以提早浏览。RAW 操作在 Worker 内执行；取消活动 RAW 操作会终止其 Worker，下一项任务使用新 Worker。已经登记的照片保留为预览待生成，重新扫描可补齐。写入预览前再次读取并校验源哈希，源文件在处理期间变化时不发布旧结果。已删除记录和旧图库会话仍不能被迟到结果恢复。

限制为单文件 256 MiB、1 亿像素及现有浏览器画布 / 导出上限。完整 RAW 解码需要 COOP / COEP 隔离；WASM 随应用按需加载，不下载模型，也不上传照片。RAW+JPG 自动合并拍摄组尚未接入独立浏览器，两者目前分别计数；桌面原有分组保持。HEIC / HEIF / TIFF 的独立浏览器图库导入仍待适配。

桌面导入的 RAW 预览通过已有 rawpy 在独立子进程中生成，共享现有单个 render 名额，逐张释放，已排队的导出优先。先读头和校验尺寸，再提取嵌入 JPEG / 位图；缺少可用嵌入图时才完整解包，以相机白平衡、8 位和 `half_size=True` 生成标准预览。部分 RGB / 有损 DNG 不受半尺寸选项影响，仍按解码器实际尺寸缩小，不放大。预览上限沿用桌面的 2560 / 560；源尺寸取 RAW 完整尺寸及方向，不取嵌入小图。

取消 RAW 预览会终止并回收子进程；180 秒超时也会清理。解码结果先留在图库缓存的临时目录，校验 JPEG、源文件前后完整哈希、尺寸 / 修改时间、当前记录后才发布，成功 / 失败 / 取消都清理临时文件。即使源字节变化后大小和修改时间被恢复，完整哈希仍可拒绝旧结果。删除记录不会被迟到的结果重新建立；取消保留已登记记录，用户重新扫描可补齐预览。直接重定位和水印读取复用同一只读快速解码器；后台导入的取消能力不等于所有同步调用都可中止。

桌面和浏览器共享常见 RAW 扩展名范围，但分别使用已安装的 rawpy / LibRaw-WASM，实际支持依赖解码器版本。嵌入图可用不代表完整像素一定可解码，编辑失败时不能拿嵌入 JPEG 冒充 RAW 源。现有共享 16 位暗房保持独立；没有更改 recipe、数据库版本或原片字节。更多机型、真实设备内存及 WebView / 安装包检查仍需后续验收，不能由这些样例通过代替。

新增自动检查使用既有公共 RAW 样例及隔离测试库，覆盖四格式批量入库与完整原始字节哈希、嵌入图 / 完整解码回退、16 位工程来源、水印 / 公开图转换、真正 Worker / 子进程终止与导出让行、取消后重扫、超时 / 文件上限、源变化拒绝、删除后丢弃、竖幅方向及损坏文件继续处理。常见格式已有真实样例检查，未把未测试的所有相机列为支持保证。
