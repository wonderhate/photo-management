# XMP 评分读取与人工操作保护

此功能属于 AfterFrame 融合开发分支。Windows / 本机服务与独立本地网页版使用同一评分规则，入口位于原有照片信息面板。

## 使用

首次导入照片时读取内嵌 XMP 和同目录侧文件中的 `xmp:Rating`，接受 0–5 的整数。已评分零分与未评分空值分别保存；负数、越界值和无效文本忽略，不自动变成排除、收藏或颜色标签。同名主体侧文件先读，具体到 `照片.jpg.xmp` 的有效值优先于 `照片.xmp`，有效侧文件评分优先于照片内嵌评分。

照片信息显示「评分来源」：照片内嵌 XMP、XMP 侧文件、应用手动评分、尚无外部评分，或旧记录（来源未知）。打开原照片查看器后，使用原有「照片信息」按钮展开面板；悬停信息栏也提供同一入口。

点击「刷新 XMP 评分」会主动重新读取外部评分。只有原来由 XMP 管理或尚无评分的记录可以更新。使用星标、快捷键或批量编辑改分，以及主动清空评分，都会标记为应用手动操作；之后重扫和刷新都保留该决定。外部文件没有有效评分时保持当前值；原片内容变化、来源不可用或保存副本损坏时提示错误。刷新本身不改变收藏、颜色标签、手工标签、图像方向或编辑参数。

旧库无法可靠区分“从未评分”和“人工清空过”，因此全部旧记录保守保护，包括空值和零分。用户仍可直接在应用内改分，旧值不会被新的导入逻辑重新填充。正常重复导入按原片哈希跳过，不隐式重新同步评分。

## 两种浏览器来源

- 关联原片目录：刷新在当前照片所在文件夹查找侧文件，可发现首次导入后新增的 XMP。只读原片和侧文件，不写回原文件、不自动弹出授权请求。
- 选择照片文件导入：照片与 XMP 已保存为图库内的副本，刷新读取这些保存的副本。不会访问原始目录中后来修改的文件。副本必须与保存的侧文件 SHA-256 一致；损坏时拒绝刷新，不能用其他评分静默替代。

保存副本与目录来源的差异沿用现有导入方式。需要重新授权目录时进入本地图库设置。原图丢失不意味着已有评分丢失。

## 存储与兼容

以下记录 AF19 引入的来源保护；后续[独立选片标记](photo-flags.md)以及[人工描述与标签来源](photo-annotations.md)及[多选筛选](photo-facets.md)与[本地人物模型保护](face-model-spaces.md)及[人物整理](person-management.md)及[连续切图保存基础](seamless-split.md)使当前格式更新为 SQLite 21 / manifest 17，评分来源和人工保护继续保留。

桌面 SQLite schema **7** 增加 `photos.rating_source`，旧照片默认 `legacy`，新导入明确记录来源。升级先备份，沿用事务和幂等迁移。配对新 RAW / JPEG 时沿用已有拍摄分组和人工决定，保留旧评分；新文件不会恢复已清空的星级。图库合并同样将手动清空视为有效决定；只有目标库中从未设置的评分才可补齐，评分与来源成对写入，旧来源库的新照片保守标为 legacy。

浏览器 manifest **6** 增加可选 `rating_source`，可读取旧 1–5 格式。首次写入前保存旧 `library.json` 的完整原始字节到 `library.before-ratings-v6-*.json`。未知未来格式、错误来源值或将新字段标为旧格式时拒写。缺少来源的旧记录按受保护处理，不补造历史。

刷新先核对原片完整哈希，读取后再核对；保存时再次读取当前记录。读取期间发生的人工改分优先于外部结果，跨库 / 同 UUID 重开后的旧浏览器会话也不能保存迟到结果。界面只合并评分字段，不把旧响应里的收藏、颜色或标签覆盖回来；评分排序及条件集合重新查询，复用既有更新路径。

## 验证

共享向量比较 Python / TypeScript 对命名空间、零分、空值、负数、格式和来源优先级的处理。合成文件与实际浏览器流程检查首次导入、主动刷新、重扫、单图 / 批量清空、读取期间人工操作、旧库原字节备份、未来格式拒写、侧文件副本损坏、RAW/JPEG 配对继承人工清空、合并保护以及旧来源库兼容、切库拒绝迟到结果及原片 SHA-256。

中英文、深色宽屏与浅色窄屏都通过原照片查看器操作验证。完整检查结果见[融合实施记录](afterframe-upgrade.md)。本功能不调用 AI，也不上传照片或回写外部 XMP。
