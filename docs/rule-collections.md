# 条件集合（融合开发分支）

影集页的「新建条件集合」按照片信息自动组织照片，Windows / 本机服务与独立本地网页版均可用。普通影集、人物影集和本地语义候选影集继续保留；条件集合使用独立 `rule` 类型，不会把旧语义关键词改成文件名匹配。

## 使用

1. 打开「影集」→「新建条件集合」，填写名称。
2. 选择字段、条件和值，可增加条件和分组。组内可选择全部满足 AND / 任一满足 OR；「排除 · NOT」反转该条或整组。
3. 查看实时匹配数量及前 12 张预览，再保存。修改评分、收藏、标签等信息后，符合规则的成员自动变化，无需重新生成候选。
4. 在卡片中「编辑条件」修改名称或规则。「打开影集」沿用图库浏览、筛选、排序及原双击查看器。规则集合不使用手动拖拽排序；删除集合只移除集合记录。

例如：「评分至少 4」AND「标签包含旅行」，或「未评分」OR「评分等于 0」。未评分与零分独立，不把缺失信息当作 0。没有照片匹配的有效集合也可保存。

## 字段与共同语义

支持文件名、相机品牌 / 型号、镜头、文件格式、颜色标签、标签、评分、收藏、RAW 标志、拍摄 / 导入时间、宽高、焦距 / 等效焦距、光圈、ISO 和曝光秒数；新增全部文字、当前 / 人工 / AI 原始描述及识别文字，详见[全文搜索](text-search.md)。没有使用 EXIF JSON、原片路径或任意 SQL 字段作为开放查询入口。

| 条件 | 含义 |
| --- | --- |
| 等于 / 不等于、数值 / 日期比较 | 字段缺失时均不匹配，包括「不等于」 |
| 未设置 / 已设置 | 显式判断空值；空字符串是已知值，不等于缺失 |
| NOT | 对已有真假结果取反，因此 NOT「评分等于 0」会包含未评分照片 |
| 标签等于 / 属于任一值 | 匹配完整标签；标签「旅途人像」不等于「旅途」 |
| 标签不等于 | 没有该完整标签，包含未标记照片；标签「未设置」指没有任何标签 |
| 包含文字 | 区分大小写的原文子串；`%` / `_` 不作为 SQL 通配符 |
| 包含（忽略大小写） | 原文子串忽略大小写，特殊字符仍按字面匹配 |
| 日期 | 按保存的墙钟时间比较到秒；日期值代表该日零点，不自动换算时区。选择一天可用 ≥ 当日零点 AND < 次日零点 |

数量、成员列表、图库 ID、分页和统计复用同一谓词。图库按既有拍摄口径在首选照片上判断规则；文件统计在各文件上判断。规则可与图库现有筛选组合；桌面原有本地语义检索也可与规则结果取交集，浏览器不因此获得尚未支持的本地语义模型能力。

## 实现与存储

共同 `PhotoQuery` 结构为 `{version:1, root:...}`；节点包含 AND / OR / NOT 及白名单字段谓词。两端严格验证版本、键、类型、日期与运算符，不接受未知字段、SQL 片段或隐式类型转换。限制为 UTF-8 JSON 32 KiB、128 个节点、深度 8、每组及「任一值」最多 32 项，文字值最多 256 个 Unicode 码点。数值有限且非负，评分仅整数 0–5。

桌面将 AST 编译为带参数绑定的 SQLAlchemy 表达式，标签用 EXISTS 子查询，先在数据库中计数 / 分页再水合当前窗口。显式空值保护让 NOT 与浏览器布尔判断一致。浏览器在元数据清单上编译谓词，不为计算成员读取原片或预览；界面统计延迟 300 ms 合并输入，并取消 / 忽略已过期响应。

桌面 SQLite 升至 **schema 5**，给影集添加可空 JSON `query`，原 `normal` / `smart` 记录与成员不改写。升级先做 SQLite backup，再以事务新增字段及版本；备份失败则拒绝升级，重开幂等。原有库迁移 / 合并保留规则。

独立浏览器清单升至 **version 4**，可读旧 1 / 2 / 3。第一次写入先把旧 `library.json` 的原始字节保存为 `library.before-rules-v4-<uuid>.json`，然后发布新格式；旧 1 / 2 来源解码备份也继续保存。固定升级备份与滚动 `library.previous.json` 分开。未知未来格式、未来 AST 版本、伪装在旧格式中的规则均拒绝写入。规则集合只存 AST，`photo_ids` 保持空数组，计数与封面从当前匹配结果生成。

公开作品导出按导出开始时的元数据快照计算集合，并与用户明确勾选的照片取交集。只导出相册名称及公开作品 ID，不带私有规则、评分、EXIF 或原路径。

本功能不调用 AI、不下载模型、不写原片或 XMP。使用当前主题变量、双语文本、原 Modal 和图库组件，没有加入新的动效。后续全文功能已增加本机 FTS5 元数据候选与既有向量交集；高级 facet、浏览器索引和完整大库性能仍由对应条目完成。

## 检查

共享夹具验证 23 组真实 SQLite / JavaScript / 浏览器 API 结果，覆盖嵌套布尔、空值 / 零分、标签、字面通配符、日期精度和参数绑定。后端另验证动态计数、分页、统计、原语义影集人工快照、混合检索交集、非法更新不落库、schema 4 备份升级与失败回退。两端界面覆盖中文深色宽屏、英文浅色窄屏、NOT 焦点保留、多值逐字输入、重开与评分后即时移出；浏览器另验跨库隔离、原始清单备份及公开导出。合成原片的 SHA-256 保持不变。

各轮实际数量及完整回归结果见 [融合开发记录](afterframe-upgrade.md)。截图、私有测试库与日志留在忽略目录，不进入 Git 或发行包。

选片条件可使用[留用 / 排除 / 未标记](photo-flags.md)三态字段，与星级、收藏和颜色分别组合；标记改变后成员与计数自动刷新。旧格式不接受新增的 flag 条件，升级沿用备份和版本检查。

[多选筛选](photo-facets.md)新增显示画幅字段，可在条件集合中保存；[当前存储格式](seamless-split.md)为 SQLite 21 / browser manifest 17，旧格式不能冒用新增画幅规则。
