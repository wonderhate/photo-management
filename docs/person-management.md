# 人物封面、合并、拆分与撤销

Windows 桌面和连接本机服务的网页可使用这些功能。独立浏览器图库尚无本地人物模型与人物分组，本次没有为它增加云端替代分析，也不增加上传或计费请求。

手动分析继续保留；设置中可主动开启[导入后本地人物分析](import-face-analysis.md)，默认关闭，仅为以后导入的新增照片排队，关闭会停止自动任务。

## 使用

- 在人物卡片点“查看照片”，在人脸检查区点“设为人物封面”；“使用自动封面”恢复自动选择。自动封面优先选已确认的有效人脸；旧的无效位置记录继续保留。
- 勾选人脸，点“移出错分”使它们回到未关联、待确认状态。原照片、其他人脸、影集及水印等作品保持。
- 勾选人脸，填写新名称，点“拆分为新人物”。新人物关联按人工操作确认；原分组的其他确认状态保持。最多一次选择 1,000 张人脸，可跨检查分页选择。
- 点“合并人物”，选择保留的目标人物及来源分组，检查名称后确认。一次最多合并 100 个来源分组，来源人脸的确认状态保持。合并属于人工身份决定，可以跨模型来源，但各来源的参考向量继续分别保存和比较，不混合向量。
- 点“整理记录与撤销”，可查看当前图库最近的封面、合并、拆分、移出及关联操作。记录随图库保存，重开软件后仍在。撤销之前会核对后续改动；存在冲突时拒绝覆盖，界面保留操作输入。

删除人物、命名、确认整组及创建影集沿用原入口；这些动作不因此成为可撤销操作。删除合并后的目标人物会一并移除它的历史人物别名，关联人脸回到待确认，原照片和已有影集内容保持。

## 旧影集的语义

人物影集仍是创建当时的普通影集快照。合并、拆分、移出和撤销均不改写成员、顺序、封面或原人物关联。

合并后保留来源人物记录，作为历史别名隐藏在活动人物列表之外。目标卡片可以打开来源人物的旧影集；打开时不会把它重新关联到目标。连续合并也保留这些入口。撤销合并后恢复来源人物卡片及原封面、参考向量和人脸归属。

拆分产生的新人物若已创建或关联新影集，撤销拆分会被阻止，避免删除新人物时悄悄解除这个新影集的关联。照片记录已删除、分组被其他操作改动、名称改变或模型来源被修改时，旧撤销记录也可能不再适用。可以先撤销依赖的整理操作；系统不会重建已删除的照片记录。

## 存储与保护

schema 13 引入 `face_covers`、`face_merges`、`face_operations`，模型空间结构仍使用 schema 12 引入的设计；后续[批量忽略与恢复](ignored-people.md)及[连续切图保存基础](seamless-split.md)使当前 SQLite 为 **schema 21**，浏览器清单为 **manifest 17**。升级前备份，备份失败不改写，重复升级幂等；旧人物、观察记录、模型来源、影集及原撤销记录继续保留。

人物改动在单个本地事务中完成。新界面提交所见人脸版本或所检查分组的摘要；撤销摘要还核对人脸不可变内容、照片内容标识、每个模型来源的参考向量、封面和合并关系。批量中任一步失败即整体回滚。旧单人脸关联接口继续兼容旧客户端；新界面会发送版本检查。

撤销记录包含压缩的私人关系元数据和参考向量，不包含图片。最多保留最近 100 次且合计压缩数据不超过 128 MiB；单次上限为压缩 8 MiB、解压 32 MiB，超限操作会拒绝并回滚。记录与数据库一起留在本机，不进入 Git、发布物或公开作品。

复制图库保留库身份及撤销历史。合并不同图库会映射人物别名、封面和人脸关系，并保留目标库的既有决定；来源库的撤销记录含外库标识和旧 ID，留在来源备份中，不导入目标库重放。

本次整理不读取模型来重新识别人脸，不下载权重，也不改写原片。缩略图从已有派生图或只读原片裁取；无效或缺失图片显示备用头像。

另见[实时人物照片与人物影集快照](live-person-photos.md)：在原有照片库内浏览当前关联，不自动更新已保存的影集。
