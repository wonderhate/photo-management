# 光影集：国内与海外共同访问的境外部署方案

核对日期：2026-10-16。当前应用版本：2.6.1。本文替代此前先买大陆备案资源的路线；尚未购买服务器、修改 DNS 或发布公网服务。

## 建议采用的组合

**EdgeOne Makers 托管网页，选择“全球可用区（不含中国大陆）”；一台新加坡轻量服务器运行现有 AI 中转；沿用阿里云购买的 `photomanagement.online`。**

国内与海外用户使用同一个正式网址。网页程序从境外边缘节点加载，照片浏览、整理和导出主要在用户电脑完成。新加坡服务器只处理中转的 AI 请求。先按个人或小规模公开使用部署，真实测试通过后再扩大开放。

这套架构能够面向国内和海外用户；你的域名在两地的实际连通性和速度尚未验证。大陆用户访问境外节点受跨境线路影响，不能仅凭“香港”或“新加坡”保证速度和稳定性。

## 网址和数据放在哪里

| 地址或位置 | 用途 | 保存内容 |
| --- | --- | --- |
| `https://photomanagement.online` | 正式网页，EdgeOne 分发 | 网页程序、图标、字体和许可证等公共资源 |
| `wss://ai.photomanagement.online/cloud-art` | 新加坡 AI 中转 | 部署程序及配置；不持久化用户图片、图库和密钥 |
| 用户原片目录 | 浏览原片 | 原始照片，保持只读 |
| 用户自己选择的图库目录 | 本地管理与恢复 | 图库元数据、预览、草稿、作品和导出等 |

普通操作：网页程序下载到浏览器 → 用户授权本地目录 → 在本地处理和保存。不会因为使用 CDN 而把用户照片传进 CDN。

AI 操作：用户确认本次发送 → 浏览器生成去除元数据的处理图片 → 境外中转 → 当前配置的千问服务 → 结果回到浏览器，保存到本地。

**普通本地功能不上传照片；云端 AI 需要发送本次处理图片。** 每位用户使用自己的独立千问密钥，密钥只用于会话和请求，不放进网页包、服务器配置或日志。中转不落盘不能代替模型服务方的数据保留政策。断连不自动重试可能计费的请求。

正式上线前固定主域名。改变协议、域名或端口会改变浏览器的站点来源，可能需要用户重新选择目录和授权，避免上线后频繁更换。

## 为什么这样选

### 静态网页用境外边缘分发

EdgeOne 的“全球可用区（不含中国大陆）”使用大陆以外的节点，自定义域名不要求 ICP 备案。“不含中国大陆”描述的是节点范围，不等于禁止大陆用户访问；实际效果需要测试。包含大陆节点的全球区域则有备案要求。[官方区域与域名说明](https://pages.edgeone.ai/zh/document/domain-overview)

必须绑定自己的域名。平台默认项目域名或部署域名在大陆网络需要有效期为 3 小时的预览链接，不能作为长期入口。[官方默认域名访问规则](https://pages.edgeone.ai/zh/document/domain-overview)

### AI 先放一台新加坡服务器

新加坡符合使用国外服务器的要求，继续使用已有腾讯云账号即可。复用现有 `cloud_relay`，暂不增加云数据库、照片存储桶或多个中转节点。

推荐试运行配置：**Linux、2 核、2GB 内存、40GB SSD、20Mbps 峰值带宽、512GB/月流量包，购买 1 个月**。这只是试运行起点，不能承诺公开服务容量。当前中转每进程最多同时处理两个请求，先观察小规模试用的等待和失败情况。

香港可在实测后作为备选。腾讯云明确提示香港入门型的大陆跨境连接可能延迟或丢包，因此不能把它当作大陆访问有保证的套餐。[官方套餐与网络提示](https://cloud.tencent.com/document/product/1207/73452)

地域创建后不能直接修改，换地区需要重新创建并迁移，所以先买一个月。[官方地域说明](https://cloud.tencent.com/document/product/1207/50103)

### 当前无需先走大陆备案资源路线

腾讯云说明香港及境外轻量服务器无需 ICP 备案，也不能作为备案资源。配合 EdgeOne 上述境外区域，本次不把 ICP 备案作为上线前置步骤。域名仍留在阿里云，不必转移注册商。[官方备案资源适用范围](https://cloud.tencent.com/document/product/243/18908)

## 接近 Windows 版体验的做法

1. 主要验收桌面 Chrome / Edge，使用 HTTPS 和原生目录授权。境外部署不能消除浏览器权限或格式支持差异，具体功能以当前 2.6.1 浏览器构建验收为准。
2. 字体和公共资源随网页部署，保留许可证，不依赖第三方字体站点。
3. 图库、预览和派生文件留在电脑；首次加载以后，普通照片操作不应持续消耗服务器图片流量。
4. 复用现有网页缓存和更新机制，检查首次加载、刷新、更新及已缓存功能的断网表现。未下载的资源不能假定离线可用。
5. 用同一组合成测试照片对照 Windows 版，检查预览、水印、中文字体和导出；原片哈希保持不变。
6. 分别备份原片和图库，验证清除站点数据后重新选择图库、授权目录的恢复流程。

## 实施顺序

### 1. 先准备静态项目

你登录 [EdgeOne Makers 控制台](https://console.cloud.tencent.com/edgeone/makers)，寻找创建项目和“直接上传”，加速区域选择“全球可用区（不含中国大陆）”。若尚未看到区域选项，先记录当前步骤，不误选大陆或含大陆区域。

由我复核当前代码并重新构建 2.6.1 发布包。旧的 `PhotoCollection-Browser-preview-20261014.zip` 是早期预览产物，不直接用于这次正式发布。先上传、绑定自定义域名并验证核心网页，AI 接通且整体验收后再公开。

### 2. 静态访问通过后，再买一个月服务器

打开 [腾讯云轻量应用服务器购买页](https://buy.cloud.tencent.com/lighthouse)，按下表核对订单：

| 项目 | 目标 |
| --- | --- |
| 地域 | 新加坡 |
| 系统 | Linux 系统镜像，优先 Ubuntu 24.04 LTS；实际选项另核对 |
| 规格 | 入门型 2 核 2GB、40GB SSD、20Mbps、512GB/月 |
| 数量与时长 | 1 台、1 个月 |
| 费用 | 核对约 30 元/月参考套餐及实际应付价；本阶段不加数据库或照片存储 |

登录和最终付款由你完成；密码、验证码、支付资料、模型密钥无需发到聊天中。静态连通性通过后再购买，减少无效支出。

### 3. 部署中转

由我复用现有 `cloud_relay/Dockerfile` 部署。HTTPS/WSS 对外提供入口，反向代理通过容器内部网络访问中转，中转的 9000 端口不映射到宿主；Windows 和原有本地服务继续回环监听。

- `PHOTO_RELAY_ORIGIN=https://photomanagement.online`。
- 网页公开构建变量 `VITE_ART_RELAY_URL=wss://ai.photomanagement.online/cloud-art`，只放地址，不放密钥。
- 代理支持 WebSocket，有效连接至少持续 900 秒，检查心跳和中断处理。
- 检查图片大小、并发和入口限制；来源检查不能替代容量控制。
- 不记录图片正文和凭证，检查错误日志及转储设置，避免用户内容持久化。
- 先验证新加坡到当前千问地址的连接，不切换提供方，不自动发起收费请求。

不直接把当前中转搬入短时函数：现有总处理上限为 880 秒，EdgeOne Cloud Functions 文档列出的最长执行时间为 120 秒，不匹配。[官方函数限制](https://pages.edgeone.ai/zh/document/limits-and-quotas)

### 4. 配置阿里云 DNS 和 HTTPS

先核对现有记录，避免覆盖其他服务。目标结构如下，**实际记录值以控制台和服务器为准**：

| 主机记录 | 类型 | 目标来源 |
| --- | --- | --- |
| `@` | CNAME | EdgeOne 的正式接入目标 |
| 平台要求的验证记录 | TXT 或指定类型 | 完整照抄项目控制台 |
| `ai` | A | 新加坡服务器实际公网 IPv4 |

没有真实目标值之前不提交示例。根域名有冲突记录时先核实用途。完成域名验证、解析和 HTTPS 后，使用正式网址验收。[官方域名接入流程](https://cloud.tencent.com/document/product/1552/127404)

AI 子域名先直连服务器，避免未经验证的 CDN 连接时限影响长任务。需要时再增加 `www` 跳转。

### 5. 国内和海外实测，再公开分享

- 国内：检查可获得的电信、联通、移动网络，包括家庭宽带和手机热点，用普通网络，记录地点、时间和运营商。
- 海外：至少一个实际目标地区；主要用户若包含欧美，补测相应地区。一次海外云机探测不能代表所有用户。
- 两地都检查 DNS、HTTPS、完整首次加载、字体、刷新更新、目录授权和导出。
- 用合成照片确认普通操作不上传照片或图库，原片哈希不变。
- 邀请 5—10 人试用，记录首次与重复打开时间、失败情况。可先以完整首次加载争取 10 秒内、重复打开争取 3 秒内作为试用目标，不能当成已达到的结果。
- 由你主动确认真实 AI 请求，检查标题、水彩、取消、断连、本地保存和计费，不自动重试。

关键访问未通过，先查 DNS、证书、静态资源、服务器线路和千问连接，再决定换节点或供应商。香港只是待测备选。以后若要求使用大陆边缘节点，再评估备案和接入路线。
