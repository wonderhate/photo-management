# 裁剪、校正与翻转（融合开发分支）

在“创作工具 → 光影暗房”打开照片或 RAW，展开“构图”，点“交互裁剪”。Windows / 本机服务与独立浏览器共用这一套界面和本地渲染器，原片只读。

## 调整构图

- 八个边角以裁框中心调整大小；拖动框内移动取景位置。框内显示三分线，框外压暗。方向键微调，Shift 加速；窄屏也支持触控拖动。
- 比例可选自由、原始、1:1、3:2、2:3、4:3、3:4、5:4、4:5、16:9、9:16、2.35:1 及 1:2.35。自由比例可独立调整宽高，固定比例在拖动和校正时保持。
- 角度尺支持 **−45° 至 +45°**，步进 **0.1°**。一次往返拖动以手势开始时的取景为基础，回到起点会恢复起始范围，避免在拖动中累计缩小。
- 左转 / 右转 90°、水平 / 垂直翻转保留。新构图配方中的这些操作会连同裁框一起变换，保留选中的内容；旧配方仍按原规则回放。
- “取景缩放”相对于当前角度的最大可用范围，支持 **1–20 倍**。照片在裁框下缩放，裁框保持屏幕位置。裁框精细缩小后可以保留更高倍率；原来的普通预览缩放仍独立保留。操作菜单的适应 / 放大 / 缩小也可用于裁剪视图，它们不修改裁区。
- 原来的左边距、上边距、宽度和高度滑块继续保留。“重置构图”只重置裁剪、校正、旋转和翻转，保留曝光、曲线等其他调整；工具栏“重置”仍重置全部编辑。

拖动一次对应一次撤销；取景缩放与角度尺也按手势合并。拖动期间保存 / 撤销 / 重做暂不可用，完成或取消后恢复。`Esc` 取消当前拖动，再次按下可退出交互裁剪。“完成裁剪”回到原预览，并将焦点还给裁剪入口。宽屏调整构图时照片区域停留在上方导航下，便于同时使用旁边的控制；减少动态效果时进入取景使用即时滚动。

## 保存与输出

“完成裁剪”只结束取景操作；“保存编辑”保存参数工程，“另存并下载”导出编辑副本，原有送入水印 / 水彩入口保持。重新打开工程后，裁剪、角度、比例约束、旋转、翻转和颜色调整一并恢复。

预览和导出使用同一个 Worker 和像素取样实现。构图使用本地仿射坐标变换与双线性插值，不需要 AI 请求。交互时先使用完整画面的有界预览，停稳后在裁框内显示当前配方的清晰裁区；旧请求不会覆盖新配方。完整画面预览只保留一个当前 URL，请求使用一个执行中任务与最新待处理值，离开时释放。

取景缩放改变选中的原片范围，较小裁区本来就包含较少像素；预览放大不会增加原始细节。正式输出沿用原有不放大规则、最长边及 JPG / PNG 选项。显示清晰度、原片解码、编辑参数和导出大小分别管理。

## 旧配方与新坐标

旧 **配方 v1** 继续保留原先的归一化裁剪、四分之一圈旋转、翻转、颜色调整和取样顺序。普通旧工程不会因打开而改写。新增校正 / 比例 / 取景缩放采用 **配方 v2**，记录解码源宽高、角度及可选比例约束。配方版本与[源解码版本](source-decoding.md)是两个独立字段。

新坐标以旋转 90° / 翻转后的图像为基础，照片围绕裁框中心自由旋转，裁框保持正向。验证的是反向映射后四个角是否在原片内；例如 45° 下的一条横向裁区，可以合法地超过未旋转时的水平边界。预览与导出使用同一个反变换，源尺寸不符、未知版本、伪装成 v1 的 v2、非法范围与比例会被拒绝。

构图本身不单独升级存储版本；当前因[连续切图保存基础](seamless-split.md)更新为 SQLite **16** / browser **12**，配方 v2 仍在编辑记录内部单独标记。浏览器第一次保存 v2 前，先完整保留原 `library.json` 字节，文件名为 `library.before-composition-v2-…json`；备份失败则不写新清单。旧程序不认识配方 v2，会拒绝打开它；需要回退时应使用此前的备份，保留完整图库及外部原片。未知的本机编辑版本也不能被较旧参数覆盖或生成新副本。

## 验证范围

隔离合成图片覆盖旧配方 **96** 组渲染字节基准、8 / 16 位、旋转 / 翻转 / 裁剪、颜色和导出边长；新角度用独立计算的原片像素中心核对取样。还检查了八柄、比例、边界、20 倍取景及屏幕裁框稳定、左右转和翻转保留内容、非法版本 / 非有限坐标，以及真实 SQLite 复制 / 合并和源文件哈希。

实际浏览器检查覆盖中英、明暗、宽窄屏、鼠标与模拟触控、一次拖动一次撤销、取消、缩放与角度尺往返、保存重开及 PNG 像素一致；另用 3201×2401 渐变图核对缩小预览和完整输出坐标，用半透明 PNG 核对清晰裁区只合成一次。它们证明当前源码流程；真实 WebView2 / 发行包验收仍按平台条目单独完成。完整结果见[融合实施记录](afterframe-upgrade.md)。
