# EXIF、XMP 与可选 ExifTool 补读

此说明对应融合开发分支。桌面 / 本机服务与独立浏览器都已接入 XMP 补读、来源记录和共同值合同。新来源的嵌入 XMP 方向通过独立解码规则统一，旧照片 / 草稿 / 工程沿用已有规则。

## 读取次序与来源

新照片保留原有读器，桌面采用 ExifRead / Pillow，浏览器采用 exifr / LibRaw。原有有效值优先；桌面可选 ExifTool 只补缺失字段，两端随后读取嵌入 XMP 与同目录侧文件。标准 EXIF 优先于 MakerNote 中的近似曝光 / 光圈值，结果不依赖 JSON 字段顺序。

同目录 `照片主体.xmp` 与更具体的 `照片原名.扩展名.xmp` 均可读取，后者优先。桌面只做固定数量的路径定位，相同文件别名用文件身份去重；浏览器在一次扫描中按来源目录及相对文件夹建索引。区分大小写时的歧义候选、同次文件选择中无法区分的多个同名照片不会猜测关联。浏览器同时支持照片 / XMP 多选及目录内读取，XMP 不计入照片总数，单独选择 XMP 会提示一并选择照片。

原始 EXIF 保留；补读值使用 `exiftool:` / `xmp-embedded:` / `xmp-sidecar:` 前缀，XMP 文件另记完整 SHA-256，各规范字段的来源写入 `PhotoCollection:MetadataSources`。这些内容可以在原照片信息的「完整 EXIF」查看。Pillow 复用已打开的图像头读取 ICC 描述，浏览器由现有 exifr 读取描述；本步骤不转换图像色彩。

| 信息 | 当前规则 |
| --- | --- |
| 相机、镜头、曝光、ISO、焦距 | 原有有效值优先，补读器补缺；非有限数值、非法整数与越界 GPS 不入规范字段 |
| 拍摄时间 | 保持相机记录的墙上时钟 `YYYY-MM-DDTHH:mm:ss`，不按运行电脑时区移动；原始时区 / Offset 字段留在来源记录中 |
| 快门 | 两端共用同一格式合同；0.8 秒显示为 `0.8`，接近标准倒数的值显示为 `1/125` 等，真实秒数始终独立保存 |
| 方向与尺寸 | 使用照片容器 / RAW 的几何信息；外部 XMP 方向、尺寸和裁剪不自动改变图像或 recipe |
| XMP 评分 | [首次导入和主动刷新读取](xmp-rating.md)，保护应用人工评分及清空操作；0 分与未评分分别保存 |
| XMP 颜色、关键词、标题和描述 | 保存为外部来源信息，不自动改写颜色标签、收藏、手工标签或作品 |
| 已登记照片 | 延续原有去重和重新定位规则；再次导入不静默刷新人工整理，专门的元数据刷新 / 监听后续实现 |

没有 EXIF 的照片仍可导入。坏 XMP、缺少可选工具、工具异常或超时均回退到已有读取。XMP 最多 1 MiB，支持 UTF-8 / 带 BOM 的 UTF-16；拒绝 DTD / 实体声明、超过 32 层或 4096 个节点的文档，不解析任意命名空间的执行内容。

两端侧文件在读取前后核对内容；浏览器选文件方式还将已经计算哈希的不可变原始 XMP 字节保存到图库，关联记录绑定照片完整哈希与侧文件哈希。目录方式保留只读关联。副本随图库备份和恢复，来源失联不会抹掉已有元数据，也不会自动请求授权。清单保存前校验 UTF-8 字节数不超过现有 64 MiB 读取上限，超限不发布半完成或无法重开的新清单；大库分片与实际性能仍属于后续工作。

方向兼容有明确版本：没有 EXIF Orientation 的 JPEG，桌面既有 Pillow 路径采用嵌入 XMP，浏览器旧路径忽略它。现在新导入来源保存 v2 方向规则，图库标准 / 高清、水印、公开导出与暗房继承同一规则；显式 EXIF 不重复旋转，缓存也区分规则与方向。旧来源缺省为 v1，重扫不自动改写，旧草稿和旧工程继续原输入。从旧图库新开暗房同样继承旧来源规则，独立打开本机文件才另行检测新规则。四角色块的实际像素、尺寸与原片哈希都有检查，详见 [源解码版本](source-decoding.md)。

## 可选 ExifTool

应用可以使用系统 PATH 中的 ExifTool，或通过 `PHOTO_EXIFTOOL` 指定一个已安装的工具文件。Windows 原生发行版应使用 `exiftool.exe`；使用 Perl 源码时可用 `PHOTO_EXIFTOOL_PERL` 指定现有 Perl。这里只读取工具，不自动下载、安装或修改全局环境。

每批最多 24 张，使用同一索引阶段的 I/O 名额；命令限定读取字段、JSON 和数值输出，禁用默认用户配置，不提供写标签参数。文件清单通过 UTF-8 参数文件传递，保留中文路径。15 秒超时、2 MiB 输出上限，取消终止自己的进程，Windows 同时终止该进程的后代；临时参数和结果文件结束后清理。当前按批启动，未宣称具备 AfterFrame 常驻进程池的启动性能。

补读前后完整哈希与文件大小 / 修改时间一致才接受结果，导入时再次核对补读绑定的源哈希；错误文件不影响同批其他可读结果。该过程会增加源文件读取，真实吞吐与内存仍需 M7 测量。ExifTool 选项依据固定版本的[官方源码与命令帮助](https://github.com/exiftool/exiftool/blob/2200871d9cef988051d2a99d67df3bda6cbb30a8/exiftool)，没有将工具的写入能力暴露给应用。

## 当前验证与剩余范围

真实 ExifTool 13.59 与现有 Perl 已验证中文文件名、相机 / 数值 / GPS、ICC、坏文件继续处理和原片哈希。官方源码中的 CR3 / IIQ 元数据夹具也已验证相机、ISO、镜头与快门补读；它们不是完整传感器文件，不用于声称 RAW 像素解码支持。测试工具源码只在忽略的测试目录，保留其原授权；未打入当前发行包。

共同 JSON 向量核对数值、墙钟日期、DMS / XMP 坐标、无效值和 EXIF / MakerNote 优先级；同一合成 JPEG 用真实 Native 读器与浏览器 Worker 比较机型、GPS、曝光、方向、尺寸及 ICC。实际浏览器检查还覆盖侧文件副本哈希 / 备份重开 / 手工整理、UTF-16 / CDATA / 注释、坏 XML、命名歧义、目录隔离、源变化拒绝、切库迟到结果、公开清单不泄露内部元数据、坏关联拒绝、窄屏英文浅色和真实 64 MiB 边界。

读取及来源规则当前均已接通。更多完整机型、专门元数据刷新 / 目录监听与正式包配置继续在对应条目验收。元数据字段仍保存在既有 `raw_exif`，浏览器另有可选的 `metadata_sidecars`；当前格式为桌面 schema 21 / 浏览器 manifest 17（含[连续切图保存基础](seamless-split.md)升级），升级前保存元数据备份，没有改写原片或外部 XMP。
