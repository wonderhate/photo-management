# 影集、人物与图表中的检索范围（融合开发分支）

从影集、人物影集、收藏、统计图表或摄影报告进入照片页后，顶部显示当前范围和计数方式。搜索、临时筛选、选项数量及列表始终在这个基础范围内进行。

人物卡片新增[实时人物照片](live-person-photos.md)入口，随当前关联更新；人物影集继续保存成员快照，两个入口在范围栏分别标明。

## 使用

- 在普通影集、智能影集或人物影集中搜索，只检索其成员；条件集合继续执行已保存规则。修改评分、选片或标签后，结果按规则重新判断。
- 「清除筛选」移除临时条件，保留进入时的影集或图表选择。「上次筛选」只恢复当前范围内的临时条件；进入其他范围后不沿用旧范围的撤销记录。
- 刷新页面、浏览器前进与后退会恢复照片页中的范围和临时条件。
- 点击范围栏的「返回全部照片」明确退出基础范围。摄影空间入口仍返回应用启动时的展示页。
- 图表与报告进入照片列表时保留当时按拍摄或按文件的计数方式。按文件查看 RAW 时，即使同组首选照片是 JPEG，也展示实际匹配的 RAW 文件；移出图库只移除选择的文件记录，原片保留。

相机、镜头、标签和曝光的自动完成选项限定在基础范围内；多选弹窗的数量还遵循其他临时条件，暂时忽略该栏自己的条件。两者沿用现有[筛选栏规则](photo-facets.md)。语义搜索和自然语言解析继续使用本机服务，不能借一次搜索解除影集范围。

## 兼容与实现

现有本机 `album_id`、`person_id` 等查询参数继续支持。照片页会把旧影集 / 人物地址转换为带图库身份的范围，同时保留原来的临时条件。新地址把基础条件和临时条件分开；本机使用 URL 查询参数，独立网页使用现有 hash 路由。

`scope` 是临时、版本化的 JSON，包含 `version: 1`、`library_id`、`mode`（`capture` / `file`）、`base` 及入口 `origin`。基础条件通过白名单校验，与临时条件取交集；不接受嵌套范围、任意路径、SQL、分页或排序字段。总量限制为 32 KiB，条件继续沿用 QueryAST 和多选筛选的校验。这个范围不增加持久化字段，[当前存储格式](seamless-split.md)为 SQLite **16** / browser manifest **11**。

本机把基础查询作为独立子查询约束列表、统计和筛选选项，并保留影集手工顺序。独立网页以当前清单中的成员集合求交集，不读取原片。范围绑定当前图库身份；地址损坏、图库不匹配或影集 / 人物已移除时显示错误，只有主动返回全部照片才解除范围。异步读取和导航使用取消、代次及编辑保护，迟到结果不能覆盖较新的选择。

旧日期筛选已与整日规则对齐：日期上界包括最后一秒的小数，日期下界从零点开始；摄影报告按实际月份末日生成入口，包括闰年。旧收藏假值、相机品牌与缺失宽高的画幅判断也与两端查询一致。

## 能力边界与验证

这里的范围是现有影集、人物和查询条件，未新增实体文件夹树。人物分组仍是本机能力；已创建的人物影集按既有快照关系使用。独立网页没有人脸模型、语义模型或 RAW / JPEG 拍摄分组，明确拒绝这些模型查询，继续按已有逐文件图库能力运行。

验证使用隔离合成图库，覆盖基础条件不可覆盖、清除 / 撤销、刷新 / 前后退、影集手动顺序、规则成员变化、关联计数、日期末秒、无效 / 跨库范围，以及按文件移除 RAW 记录后 JPEG 与两份原片 SHA-256 保持。中文深色宽屏与英文浅色窄屏沿用当前主题和减少动态设置。完整结果见[融合实施记录](afterframe-upgrade.md)。
