# 储卫民摄影网站：UI 布局与动画分析

分析对象：[cn.chuweimin.com](https://cn.chuweimin.com/)。检查日期：2026-10-11。

**核心判断：这个网站用“大幅摄影＋编辑式排版”建立观看节奏，再用光圈、取景框、胶片、显影、车窗和微光等摄影元素组织交互。它最有价值的地方，是让作品题材决定浏览方式，同时保留一致的导航、字体和操作规则。**

## 检查范围与证据

本次使用独立 Chrome 检查实际页面、滚动、悬停、路由切换和大图浏览，并核对网站公开 CSS、JavaScript 模块。桌面视口为 **1440 × 900**，手机模拟视口为 **390 × 844**；另检查了浏览器“减少动态效果”模式。

实际检查：首页、格陵兰系列、青藏铁路系列、烂尾楼系列、摄影教程、个人介绍、联系页、照片分析工具。格陵兰大图浏览同时检查了桌面和手机布局，验证了方向键切换与 Escape 关闭。

以下标记区分证据强度：

- **实测**：本次浏览器中观察到，包含截图、DOM 或计算样式。
- **源码**：公开资源中有明确实现，未必逐项触发。
- **判断**：基于观察提出的设计解释或迁移建议。

绿色未来的云幕、线上展厅和地图配置有源码依据；本次未完整操作线上展厅、3D 照片和全部小游戏。手机检查属于浏览器模拟，未替代真实手机的触控、陀螺仪和性能验证。参数与页面内容对应上述日期的在线版本。

## 1. 整体视觉语言

### 黑色展场，照片承担主要色彩

界面背景接近黑色，正文为白色与不同透明度的灰色，金色只用于重点。照片的冷暖关系因此成为页面最强的色彩来源。首屏的大片蓝色雪景与金色品牌文字相呼应；切换到铁路题材时，车厢和高原景色自然改变页面氛围。

整体并非纯平面黑底：全局叠加了轻微噪点、边缘暗角和顶部暖色光晕。其作用是把网页组织成连续的观看空间。**判断：这种处理适合影像展览，但涉及照片色彩判断的工具界面，应当减少氛围叠层。**

公开样式中的主要色彩如下。[来源：全局样式](https://cn.chuweimin.com/assets/index-tkUJz1wd.css)

| 角色 | 值 | 实际用途 |
|---|---|---|
| 黑色 | `#000000` | 主背景、导航、页脚 |
| 深黑 | `#0a0a0a` | 深色层次、摄影转场 |
| 深灰 | `#1a1a1a` | 卡片底色、信息区域 |
| 金色 | `#C9A558` | 分类、选中项、数字、箭头、装饰线 |
| 白色 | `#ffffff` | 主要标题和正文 |
| 半透明白 | 依场景使用约 30%–90% | 次要文字、边框、说明 |

专题背景还存在细微变化：格陵兰偏深蓝，铁路偏暖黑，烂尾楼和绿色未来偏中性黑。这些差异让专题保留个性，又共享同一品牌。[来源：专题配置](https://cn.chuweimin.com/assets/usePhotos-x3nRboZW.js)

### 中文衬线承担表达，无衬线承担操作

大标题使用 **Noto Serif SC / 宋体类字体**，强调粗细反差和字形结构；界面控件、数字与英文使用 **Manrope / Geist 等无衬线字体**。这是视觉层级的核心：标题有作品集的表达力，按钮、参数和筛选则保持清晰。

实测首页中文姓名约 **122.4px**，系列区标题 **96px**，系列卡片标题 **36px**；手机对应约 **50.7px、48px、24px**。英文分类标签字号较小、字距较宽，与中文大标题形成对照。

**判断：高级感主要来自字体比例、图片质量和留白。金色与动画负责强化这套结构。**

### 首屏的重点是稳定的文字与变化的影像

首屏使用 `100svh`，本次桌面高度为 900px，手机为 844px。`svh` 有利于避免手机浏览器地址栏变化直接扰乱首屏高度。

背景采用铺满容器的裁切方式，叠加黑色渐变与暗角。左下区域依次出现短横线、说明、中文姓名、英文/网名、资历和两个按钮。其余大部分区域留给照片。

主要按钮为白底黑字胶囊，次要按钮为透明底细边框。**判断：用户无需理解完整站点，即可区分“进入作品”和“了解作者”。**

轮播切换的是背景影像，作者信息保持稳定；用户不会因每次换图重新寻找操作位置。右下指示器以细横线为主，选中项扩大并显示名称，避免五个系列同时占据画面。

### 首页采用宽容器与稀疏分区

常规内容最大宽度为 **1600px**。1440px 视口下左右内边距均为 **40px**，可用宽度为 **1360px**；手机左右为 **20px**。系列卡片间距为 **20px**。

主要分区桌面上下留白常用 **144px**，手机收缩到 **96px**。这些尺寸让页面更接近画册展开，而非信息密集的管理后台。

![首页系列作品卡片](/C:/Users/wonder/.codex/visualizations/2026/10/11/01a1298e-924e-7cc2-b0b1-70cf3fb13a87/desktop-series-cards.png)

桌面主推卡片本次约 **1360 × 583px**，比例接近 **7:3**；普通卡片约 **670 × 447px**，接近 **3:2**。手机统一为约 **350 × 233px** 的单列卡片。主推层级主要在桌面成立，手机优先保证观看面积与文字可读性。

卡片文字压在左下方暗部，右下放圆形斜向箭头。英文名称和年份在上，中文标题居中，说明和数量在下，形成一致的信息顺序。

## 4. 动画系统：从慢速氛围到快速操作反馈

网站核心动画可以分为三类：

1. **观看氛围**：缓慢运镜、颗粒、暗角、极光、飘雪。
2. **摄影叙事**：光圈开场、快门转场、暗房显影、车窗移动、手电筒照明。
3. **操作反馈**：菜单、下划线、按钮、筛选、照片切换、缩略图选中。

缓慢运动用于让观看停留，短动画用于让操作明确。两者共享金色、细线和较柔和的减速曲线。

| 胶片颗粒 | 极低透明度噪点分步移动 | 透明度约 3%；1.1s、4 步 | 计算样式＋源码 |
| 环境光晕/暗角 | 暖色光与边缘暗角缓慢呼吸 | 9s | 计算样式＋源码 |

滚动显现由 `IntersectionObserver` 触发，基础组件阈值为 **8%**，显现后停止观察；另有标题组件使用 20% 阈值。它主要是进入视野时触发的动画，不能笼统描述成所有区块都跟随滚动连续运动。[来源：Reveal 组件](https://cn.chuweimin.com/assets/Reveal-DR4BvAjo.js)

缓动常用 `cubic-bezier(.16, 1, .3, 1)`：起步较快，尾段缓慢收敛。光圈转场则使用更剧烈的 `cubic-bezier(.87, 0, .13, 1)`，强化一次明确的开合动作。

### 快门转场是最明确的品牌动画

![路由切换中的光圈叶片](/C:/Users/wonder/.codex/visualizations/2026/10/11/01a1298e-924e-7cc2-b0b1-70cf3fb13a87/desktop-shutter-transition.png)

本次从首页点击进入系列作品，实际捕获到六片光圈叶片组成的遮罩。转场同时包含黑幕、金色闪光和新页面的微小缩放/亮度变化。

**判断：它把“打开一个新页面”表达为“通过镜头进入另一组作品”。** 对个人摄影网站，这种强记忆点有价值；对于频繁切换页面的管理软件，550ms 的全屏遮罩会增加操作负担。

### 要区分样式定义与实际生效

首页卡片当前可能使用 `<video>` 封面。本次悬停主推卡片时，箭头确实移动了 6px，但视频元素的计算 `transform` 仍为 `none`；`1.07` 倍放大规则明确针对 `img`。

因此，准确描述是：**图片封面定义了放大效果；本次视频版主推卡片已确认的是箭头、颜色和取景框反馈。** 视频播放本身也受加载状态与降级策略影响，不能把支持循环视频等同于每张卡片在每种网络下都正在播放。

公开 CSS 本次包含 **72 个关键帧定义**，其中还有工具、游戏和特殊模块的动画。这个数量不是首页同时运行的动画数量。

## 5. 专题页：共用骨架，用题材改变观看方法

专题页骨架一致：

**全屏封面 → 系列说明 → 浏览控件与画廊 → 与作品相关的补充内容 → 下一系列。**

标题、年份、作品数量和获奖信息依次排列；说明区使用较窄文本容器，并提供展开全文。图库最大容器宽度扩大到 **1800px**，给影像更多空间。

| 专题 | 浏览方式与氛围 | 设计解释 | 验证范围 |
|---|---|---|---|
| 格陵兰 | 保持比例的拼排行；极光、雪粒；拍摄足迹与气候信息 | 冷色影像延伸为极地观看环境 | 页面、画廊、大图实测 |
| 青藏铁路 | 大幅横向画廊；自动前行；站点、里程与海拔 | 用户的横向观看接近乘车经过风景 | 横向画廊与信息变化实测 |
| 火车看世界 | 与铁路类似的横向轨道及列车光影配置 | 延续车窗叙事的交互规则 | 专题配置确认 |
| 烂尾楼 | 手电筒照明；“微光/常亮”切换；楼盘后续故事 | 用局部可见性呼应夜景、生活与微光 | 移动鼠标照明实测 |
| 绿色未来 | 云幕开场、地图与线上展厅入口 | 用空间和地理信息扩展观看 | 配置确认，未完整操作展厅 |

这些差异在[专题配置](https://cn.chuweimin.com/assets/usePhotos-x3nRboZW.js)中是明确的分支，不是根据视觉风格推测的功能。

### 格陵兰：保持照片比例的拼排行

![格陵兰说明、筛选与画廊](/C:/Users/wonder/.codex/visualizations/2026/10/11/01a1298e-924e-7cc2-b0b1-70cf3fb13a87/desktop-gallery.png)

画廊上方依次安排标题/分享/数量、作品范围、拍摄年度。选中筛选为金底黑字，其他选项为细边框，信息状态很清楚。

主体不是整齐裁切的方格。本次第一排五张照片高度约 **178px**，宽度约 **245–267px**；下一排随照片比例调整宽度和高度，包含更窄的竖图。

**判断：更准确的结构描述是保持比例的拼排行。** 界面提供的“瀑布流”名称不能替代实际排版观察；它与每列独立堆叠的传统 Masonry 有区别。保持完整比例有利于阅读摄影构图，代价是布局需要根据图片尺寸重新计算。

极光与雪粒是在照片之外延伸专题气氛。本次画面中实际出现了极光背景、雪粒和 Kp 信息卡。其题材匹配度很高，但长时间或批量看图时宜允许更安静的模式。[页面：格陵兰系列](https://cn.chuweimin.com/series/greenland)

### 青藏铁路：让横向浏览成为列车旅程

### 烂尾楼：把光标变成手电筒

![烂尾楼系列手电筒效果](/C:/Users/wonder/.codex/visualizations/2026/10/11/01a1298e-924e-7cc2-b0b1-70cf3fb13a87/desktop-flashlight-gallery.png)

这里用的是 CSS `mask-image` 与指针更新，而非一套大型灯光引擎。“常亮”入口很关键：用户既能体验专题，也能恢复完整观看。[页面：烂尾楼](https://cn.chuweimin.com/series/faint-light)，[实现：FlashlightGallery](https://cn.chuweimin.com/assets/FlashlightGallery-1XAGwhfa.js)

**判断：手电筒效果承担了叙事。用于普通图库时，限制可见性会妨碍快速选择，应仅作为明确选择的展示模式。**

## 8. 手机端与减少动态效果

网站以约 **768px** 为关键桌面/手机分界，在布局之外还调整动画成本。

| 项目 | 桌面 | 手机/减少动态效果 |
|---|---|---|
| 主导航 | 横向导航＋悬停下拉 | 全屏菜单＋分类展开 |
| 内容边距 | 通常 40px | 通常 20px |
| 首页系列区 | 两列，首卡跨两列 | 单列，统一约 3:2 |
| 首页统计条 | 五列 | 两列 |
| 持续颗粒、暗角呼吸、封面 CSS 运镜 | 正常启用 | 手机 CSS 关闭这些持续动画 |
| 暗房显影 | 亮度/对比度/色彩/模糊共同变化 | 手机改为透明度淡入，约 900ms |
| 部分图片加载过渡 | 透明度、滤镜、比例 | 手机主要过渡透明度 |
| 取景框光标 | 鼠标跟随 | 触摸场景不展示鼠标效果 |
| 大图信息 | 较完整 EXIF＋缩略图 | 压缩 EXIF，保留更多入口与横向缩略图 |
| 减少动态效果 | — | 取消显现位移、持续运镜与开场等动画 |

手机关闭的是上述 **CSS 持续动画**，并不自动意味着所有视频都禁止播放。媒体播放与图片降级还由独立逻辑决定。

减少动态效果模式已实测：没有开场层，页面没有正在运行的关键帧动画；尚未进入视野的显现区块也直接显示为 `opacity: 1`，无位移。说明其适配不仅是把动画变快，还保证内容可直接读取。

这些行为可以在[响应式样式](https://cn.chuweimin.com/assets/index-tkUJz1wd.css)与[媒体/导航逻辑](https://cn.chuweimin.com/assets/index-BpJ3E19k.js)中核对。

## 9. 实现机制与实际代价

公开资源明确显示 React 组件、Vite 模块拆分及大量 Tailwind 风格工具类。核心运动主要通过 **CSS 关键帧/过渡、IntersectionObserver、requestAnimationFrame** 实现。极光、雪粒等特殊模块使用 Canvas/WebGL 路径；还存在 Three.js 相关的独立模块。不能据此说全站所有动画都依赖 3D 引擎。

可见的节制措施包括：模块按路由加载，图片渐进加载，部分媒体进入视野后启动，胶片带离屏暂停，手机降低滤镜成本，以及减少动态效果适配。[主入口](https://cn.chuweimin.com/assets/index-BpJ3E19k.js)、[图片加载组件](https://cn.chuweimin.com/assets/BlurImage-BTGKvf5p.js)

本次初次直接打开部分专题时，曾短暂出现预渲染的简化内容或加载层，随后被完整应用替换。**判断：这种策略兼顾可读取的初始内容与丰富交互，但网络慢时的等待和布局交接仍会影响首印象。** 本报告的专题截图使用加载后的正式界面。

从实现上看，以下内容需要控制使用范围：

- 全屏颗粒、视频、极光和雪粒会持续占用绘制资源。
- 大面积模糊、亮度和对比度组合过渡，比单纯透明度/位移更复杂。
- 每次导航的光圈遮罩、反复显现的卡片，会延缓高频任务。
- 低透明度小字和长字距标签适合点缀，关键操作与说明需要保持可读性。
- 横向列车和手电筒改变了常规浏览预期，需要保留暂停、常亮或普通视图。

这些是设计与实现层面的成本判断。本次未运行 Lighthouse、真实设备帧率、耗电或网络基准，不将它们写成已测得的性能问题。

## 10. 最值得借鉴的设计与“光影集”对应关系

考虑“光影集”需要导入、筛选、EXIF、统计、水印草稿和导出，最适合借鉴的是图像层级、浏览器结构和操作反馈；大型专题动画更适合独立的展示模式。

| 网站设计 | “光影集”适用位置 | 建议 |
|---|---|---|
| 黑色画布、层次灰与少量金色 | 展示模式、影集详情 | 可作为视觉主题；保留现有主题选择与清晰文字 |
| 中文衬线大标题＋无衬线控件 | 摄影报告、影集封面 | 表达区用衬线，表单与工具条保持无衬线 |
| 一张主推＋多张次级作品 | 首页影集、年度精选 | 用内容优先级决定卡片面积 |
| 保持照片比例的拼排行 | 图库浏览 | 降低构图裁切；同时保留列表和密度切换 |
| 全屏大图＋底部缩略图＋EXIF | 照片详情、对比入口 | 优先借鉴，服务实际浏览 |
| 明确的金色选中态 | 标签、筛选、待导出状态 | 用颜色配合文字/图标，状态可快速识别 |
| 箭头、边框与轻微提亮 | 影集、水印作品卡片 | 做直接反馈，避免移动编辑画面 |
| 手机单列与全屏菜单 | Android/网页窄屏 | 按触控重新组织，不复制悬停行为 |
| 渐进图片加载 | RAW/HEIF 预览与图库 | 清楚区分预览与原始文件，允许加载状态 |
| 首次光圈开场 | 可选作品展示入口 | 若使用，应可跳过，不影响启动与恢复任务 |
| 快门式页面切换 | 低频作品展示 | 作为可选氛围；高频管理页面使用更短反馈 |
| 极光、雪粒、手电筒、列车 | 专题展映模式 | 用户明确开启时使用，并提供普通浏览 |

**判断：优先级应是“完整看照片、清楚看状态、顺畅做操作”，随后再增加摄影氛围。** 网站现有工具页已经展示了这种密度切换，可以作为管理界面的参考。

建议迁移顺序：先建立颜色、字体、间距和大图浏览结构；再完善卡片与控件反馈；最后按具体影集题材增加可选的展示动画。这里是设计建议，没有修改“光影集”的程序。
