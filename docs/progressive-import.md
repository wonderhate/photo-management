# 渐进导入与预览补齐

此说明对应融合开发分支，适用于 Windows／本机后端与独立本地网页版。导入先登记原片和元数据，再分批生成缩略图、标准预览；等待预览的照片已经可以搜索、选中、评分、打标签、加入影集或移出图库。保留原片只读、内容去重、来源重连和各运行时已有格式支持。

## 批次与计数

扫描先确定文件总数。校验与入库阶段计算完整 SHA-256 并读取元数据，原整体任务的成功、跳过、失败计数继续按文件统计。缩略图和预览使用独立阶段及 `preview_total`／`preview_processed`／`preview_failed`，不会把一张照片按三个阶段重复计数。

第一批最多 24 张需要预览的照片，后续批次最多 100 张；距离上一批结束超过 8 秒时也会提前处理已登记的小批，最后补齐不足一批的照片。时间边界在文件之间检查，不能保证单个慢文件在 8 秒内完成。首批较小是为了提前提供可见照片，后续较大批次减少阶段往返，不代表所有设备已测得相同的首屏耗时。

本机使用短事务逐张登记；浏览器先在内存收集当前小批，再用已有清单事务发布，避免每张元数据都重写整个清单。取消时保存已经校验完成、仍属于当前图库的小批。浏览器仍执行图库 ID、目录句柄、会话代次和 revision 冲突保护。

## 解码与来源

本机沿用 ExifRead／Pillow／rawpy：普通图片先验证容器而不生成完整 RGB 预览；RAW 沿用元数据回退，解码失败不丢失登记。JPEG 后来与已经标记的 RAW 配对时，新记录继承已有的收藏、评分、颜色和标签，不覆盖已有记录的人工修改。

网页版仍支持 JPEG、PNG、WebP、AVIF 的图库导入。JPEG、PNG 和 WebP 从容器头读取尺寸；AVIF 的项目变换由浏览器解码器判定，元数据阶段可能需要一次尺寸解码。独立图片 Worker 再按批生成原有 480 缩略图和 1600 标准预览。本机继续使用原有 560／2560 预览及色彩、方向、透明背景规则。网页版图库批量 RAW 尚属独立待办，不能据此宣称已经支持。

预览开始前核对已登记来源的完整哈希；图库切换后的迟到结果不能写入新库。图像工作结束只更新当前记录的派生图像字段，不回写旧评分、标签或影集关系，也不会恢复用户已经删除的记录。自动化检查使用隔离合成原片，并核对处理前后的原片哈希。

## 等待、失败和查看器

待生成照片显示「预览正在生成」，不请求尚不存在的缩略图 URL。新浏览器记录使用可选 `preview_status` 字段，旧清单默认保持可用预览；本机状态从已有路径与错误字段推导。无需新数据库 schema 或清单版本。

容器校验已经通过、但像素解码失败的照片仍保留登记，单独记录预览错误；这类错误不把已成功登记的照片改算成入库失败。再次明确导入相同内容时，跳过重复登记并补齐缺失或失败的预览，不自动重放已取消任务。

双击仍打开原照片查看器。若标准预览尚未就绪，显示等待提示；只对这张待生成照片每秒读取一次本地状态，成功后自动显示。刷新只合并派生图像字段，不覆盖同时作出的收藏、评分或标签修改。关闭或切换照片会取消等待，旧响应不能重新打开查看器或替换下一张照片。

图库定时刷新沿用现有卡片和滚动容器，保留可见窗口的有界元数据；加载请求每批最多 200 条。新增照片和预览就绪不会清空选中状态、跳回页首或移走输入框焦点。真正变更筛选或排序时再重建布局。

## 资源和取消

导入整体保留 io 名额，每张预览单独借用 render 名额，完成后立即释放。已排队的导出先取得下一次渲染名额；不会让一整批预览持续占用渲染资源。只允许 io → render 借用，导出不反向等待 io，避免循环等待。借用不重复占用整体任务的 64 项容量。

取消等待中的预览阶段不会开始解码。已经解码中的一张图片可以完成并保存；之后的照片不再开始。完成的入库阶段、记录、预览和导出保持，原片不删除、不覆盖；浏览器若已关闭或切换图库，迟到结果直接放弃。已完成图片可能留下尚未引用的应用自有派生缓存，后续缓存回收单独处理。

更完整的任务生命周期、云端提交边界和不自动重试行为见[任务与恢复](tasks-and-recovery.md)。此功能只处理本地图像，不新增付费请求、模型下载或照片上传。

可选的[导入后本地人物分析](import-face-analysis.md)默认关闭。启用时在原导入流程结束后，只为这次新增记录建立独立本地任务；重复记录、旧预览修复与重新定位不会触发整库分析。模型未就绪或分析失败不改变已完成的导入。
