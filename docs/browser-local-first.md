# 固定网址浏览器版：实施与部署

作品展示、浏览器 RAW 与后期工具的新增能力及部署要求见 [数字暗房说明](browser-darkroom.md)。当前融合分支增加了 [RAW 批量入库](raw-import.md)，下文基线以当前分支新增格式说明为准。


基线 2.5.1；实施日期 2026-10-14；分支 `codex/browser-local-first`。现已实现独立的纯浏览器构建与可选千问中转服务。公网尚未部署，没有已交付的网址；上线需要域名、托管账户和 HTTPS 配置。

## 已实现的使用方式

用户用桌面版 Chrome / Edge 打开固定 HTTPS 网址，选择一个空目录创建图库，再授权另一个原片目录。无需安装或启动本机服务。照片解析、去重、缩略图、预览、影集、收藏、评分、标签、筛选、时间线、器材统计、月报 / 年报、镜头报告、对比、水印署名、草稿和导出均在本机执行。界面沿用现有主题、中英文及减少动态效果设置。

原片目录只申请读取权限；图库目录保存 `library.json`、上一份元数据、预览、草稿、作品和 `exports/`。删除图库记录不删除原片。同名导出自动编号。IndexedDB 只缓存授权目录句柄；关闭后可以重新打开已有目录，清除网站数据后也可重新授权恢复。浏览器图库独立于 Windows SQLite 库。

当前支持 JPEG、PNG、WebP、AVIF 和 LibRaw 可读取的 RAW；解码能力取决于浏览器与固定版本解码器。不支持 HEIC / TIFF 图库导入、RAW+JPG 分组、人脸、本地语义模型和智能影集。保留普通影集。水印使用 Canvas 本地渲染，共享预览 / 导出布局，但不能承诺与 Windows Pillow 的像素及色彩管理完全一致。RAW 预览优先嵌入图，编辑仍用完整 16 位线性源；暂无完整 ICC 工作流、自动文件夹监控或跨设备同步。

首次联网加载后，Service Worker 缓存应用资源；字体和品牌资源按使用情况缓存，未加载过的艺术字体仍需先联网。更新等待旧页面关闭，避免强制刷新编辑中的页面。普通使用只下载程序资源，不发送照片、EXIF 或图库数据；CDN 仍会收到常规静态资源请求。

## 本地启动、构建与验证

需要 Node.js 22.12+，推荐当前受支持的 LTS；已安装前端依赖时无需重复安装。

```powershell
npm ci --prefix frontend
npm run dev:web
# 访问 http://127.0.0.1:5175，选择本地目录
npm run build:web
npm run test:web
npm run test:web:cloud # 模拟云连接，无真实付费请求；结束后恢复正常构建
npm run test:frontend
npm run test:relay
```

产物仅为 `frontend/dist-web/`。不要上传仓库根目录、`.venv`、`.env`、私人图库、日志或模型。构建保留字体 OFL 许可证、品牌和署名来源记录。原来的 `npm run build`、Windows 和本机后端启动方式继续使用原构建，不切换为浏览器模式。

## 静态站点部署

推荐在本机运行 `npm run build:web` 后，直接上传 `frontend/dist-web` 的内容；仓库根目录的 `edgeone.json` 提供响应头，浏览器构建会自动复制到发布目录。当前[官方构建配置](https://pages.edgeone.ai/zh/document/edgeone-json)列出的预装 Node 22.11 低于本项目 Vite 的要求，直接上传预构建产物可避开这个差异。若改用 Git 导入构建，先确认账户支持 Node 22.12+，再设置前端依赖安装、`npm run build:web` 和输出目录 `frontend/dist-web`，不可沿用默认桌面构建。在 EdgeOne 选择符合实际访问地区的节点和域名方案，绑定自己的固定域名及证书。大陆加速按托管平台要求完成域名备案及接入；本仓库不包含代办或购买步骤。配置依据 [EdgeOne 官方配置说明](https://pages.edgeone.ai/zh/document/edgeone-json)。

也可直接上传 `dist-web` 内容到已有静态托管。应用使用 `/#/...` 路由，无需把所有请求重写为首页。将 `index.html`、`sw.js` 和 manifest 设为重新验证；带哈希的 `/assets/*` 长期缓存；`/local-assets/*` 短期缓存。其他主机应照搬 `edgeone.json` 中的响应头，特别是 CSP、禁止嵌入及 no-referrer。资源必须从站点根目录提供，不支持直接双击 HTML 或任意子路径部署。

确认正式域名后保持来源地址稳定：协议、域名或端口改变都会影响授权句柄与网站缓存。用户的磁盘数据仍在原图库目录，但需要重新选择授权。

## 可选 AI 中转

本机运行 `npm run preview:web` 会同时启动静态预览和仅监听 `127.0.0.1:9000` 的 AI 中转。通过 `http://127.0.0.1:4175/` 打开页面，在水彩工坊的“AI 服务设置”输入本次会话的千问密钥并保存，即可启用生成按钮。启动中转不会调用外部 API；每次生成仍需单独确认。运行环境使用项目的 `.venv`，须安装 `cloud_relay/requirements.txt` 中的依赖。

公开网站默认不设置中转时，所有本地功能可用，云端生成不可用。可在“AI 服务设置”填写自有的 WSS 中转地址，也可通过 `VITE_ART_RELAY_URL` 提供构建默认值。界面单独显示密钥和中转地址状态；“已配置”表示参数保存成功，不代表已验证账户权限或服务连通性。中转地址保存在浏览器偏好中，密钥只在页面内存中。配置示例见 `frontend/.env.example`；`VITE_*` 会进入公开 JS，只放中转地址，绝不能放千问密钥。

用户在设置中输入自己的独立千问密钥，仅存在当前页面内存，刷新后重填。填写密钥后点击“保存设置”，无需关闭再打开工坊。每次标题建议或水彩生成，确认框显示中转主机、千问目标、模型和可能计费说明。确认后，仅发送去除元数据的缩放图片以及本次必要参数。密钥经自有中转到固定千问接口；不复用 OpenAI 凭证，不自动重试。

标题建议跟随当前界面语言：中文界面要求标题与说明都使用简体中文，英文界面要求英文；网页版中转与桌面版共用语言指令。已有建议不会自动翻译，切换语言后须由用户重新点击“建议标题”。

服务代码在 `cloud_relay/`，共享原有千问协议，不导入图库数据库或桌面凭证。只在内存处理中转内容，不建立数据库、对象存储、上传目录或持久任务队列。关闭请求访问日志；云平台网关 / APM 也须关闭正文、Header、WebSocket 内容采集，避免日志落下图片或凭证。服务会瞬时接触图片和密钥，因此不能把 AI 功能描述为“照片从不离开电脑”。

本机调试（PowerShell；只有执行 AI 操作才可能触发外部请求）：

```powershell
$env:PHOTO_RELAY_ORIGIN='http://127.0.0.1:5175'
.venv/Scripts/python.exe -m uvicorn cloud_relay.app:app --host 127.0.0.1 --port 9000 --ws-max-size 131072 --no-access-log
# 在另一个终端设置后重新启动前端
$env:VITE_ART_RELAY_URL='ws://127.0.0.1:9000/cloud-art'
npm run dev:web
```

只有本机开发和预览服务的 CSP 允许回环地址的 9000 端口 WebSocket；公开静态构建继续只允许 WSS。本机中转默认只接受 `http://127.0.0.1:4175` 来源，使用其他开发地址时应按上述命令设置对应的 `PHOTO_RELAY_ORIGIN`。

WebSocket 传输上限为 128 KiB，为 64 KiB 图片块的压缩与帧开销留出空间；应用仍拒绝解码后大于 64 KiB 的块，并保留 8 MiB 图片总量限制。旧服务使用 `--ws-max-size 65536` 时，难压缩图片块可能触发 1009 断连；请更新本机启动命令或容器，而不是重填有效密钥。真实连接回归使用合成噪声图片及模拟模型，未调用付费 API。

云端使用仓库根目录为 Docker 构建上下文：

```powershell
docker build -f cloud_relay/Dockerfile -t photocollection-relay .
```

`cloud_relay/Dockerfile.dockerignore` 只允许服务、依赖清单及两个共享协议文件进入上下文。镜像无用户图库、密钥及测试数据；云容器监听 9000，部署平台对外提供 WSS，设置 `PHOTO_RELAY_ORIGIN=https://你的正式网站域名`，不得带结尾斜杠。前端构建设置 `VITE_ART_RELAY_URL=wss://你的中转域名/cloud-art`。CSP 的 `connect-src` 上线时可将 `wss:` 收紧为这个确切来源。

可部署到支持容器、WebSocket 和至少 900 秒连接的服务。CloudBase HTTP / WebSocket 函数的 `type=HTTP`、`protocolType=WS`、`timeout=900` 配置有[官方说明](https://docs.cloudbase.net/cli-v1/functions/configs)；具体镜像入口、WebSocket 网关、地区和带宽须在实际账户验收。不要部署到短时边缘函数后把超时当作模型失败重试。

入口为 `/cloud-art`，`/health` 只检查来源配置，不验证密钥或模型权限。每个进程最多处理两个 AI 请求；输入和输出各不超过 8 MiB、最长边不超过 1536，帧不超过 64 KiB，以约 91 KiB/s 传输，客户端 / 服务端总预算 880 秒。平台仍须提供足够连接时长。实例内限额不是全站并发限额，实际账户还应配置实例上限及费用告警。

断连后结果和计费状态可能未知。页面刷新会把未完成任务标为中断，绝不重新发起生成。没有服务端持久队列，因此无法承诺关页后找回尚未写入本地的结果。已有作品和草稿随图库备份恢复。

## 保存与恢复边界

- 每次元数据写入先校验，关闭写入流后才显示成功；保留 `library.previous.json`。串行写入、同源 Web Lock 和磁盘修订号防止旧标签页覆盖新内容。发现冲突后重新打开图库；避免多浏览器、网盘同步工具同时编辑。
- 设置中的完整图库备份复制派生图片、草稿、作品和导出，最后才写有效 manifest。恢复时选择新生成的 `PhotoCollection-...` 子目录。原片需另行备份。
- 元数据损坏时可在启动页恢复上一份；保留损坏文件以便人工排查。若两个元数据文件都损坏，需要外部备份。
- 原片移动后，在设置重新选择目录，再次导入可按内容哈希关联缺失照片并保留记录。授权撤销或浏览器清理不会删除磁盘图库。
- 当前元数据是完整 JSON 快照，64 MiB 读取上限；导入每 16 张提交一次，中断可能留下未关联的派生文件。旧作品版本保留以维持草稿引用，不自动清理。未完成十万级图库性能验收，不承诺与 Windows 大库性能相同。文件 Blob URL 保留到图库关闭，避免仍在显示的照片因缓存淘汰而失效；大库内存占用仍需实测。
- 单个输入上限 256 MiB / 100 MP；导出 Canvas 最长边 16000、总像素 64 MP，受设备内存影响。AI 输入最长边 1536，标题输入 1024。

浏览器 EXIF 合成夹具测试使用开发环境的 Python / Pillow；运行测试前须备好仓库 `.venv`（可用 `PHOTO_TEST_PYTHON` 指定）。
